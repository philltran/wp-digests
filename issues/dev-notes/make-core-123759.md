# React 19 upgrade temporarily reverted in Gutenberg

## Summary

The Gutenberg plugin release 23.3.2 temporarily reverts the React 19 upgrade shipped in 23.3.0 back to React 18 due to runtime incompatibilities breaking third-party plugins. This rollback resolves crashes caused by React 19's stricter validation of JSX element shapes, which actively rejects objects generated by legacy React 18 `jsx-runtime` helpers. The core team reaffirms the goal of upgrading to React 19 in WordPress 7.1 while pausing to design a safer, incremental migration path.

## Impact

- **Plugin & theme developers**: No immediate code changes required. Plugins relying on the default WordPress/editor environment will see crash resolution; any that independently adopted React 19 during the v23.3.0 window must revert to v18 expectations or await the upcoming compat layer.
- **Hosting & platform teams**: No configuration shifts or dependency overrides needed. Maintain stable releases at ≥23.3.2 for guaranteed editor stability.
- **Editors & site owners**: No action required. Third-party block crashes are resolved by the rollback.
- **Roadmap/Next Steps**: An experimental feature flag to toggle between React 18 and 19, along with a dedicated compatibility layer, will be developed to enable a controlled upgrade for WordPress 7.1.

## Technical details

The change rolls back the `react` and `react-dom` dependency versions from v19 to v18 within the Gutenberg plugin package. The root cause identified is a runtime shape mismatch in `react/jsx-runtime`: React 19 enforces strict validation on JSX element objects and actively rejects payloads generated by older React 18 runtimes. This triggers immediate crashes when third-party plugins render components using incompatible object signatures. The revert restores the previous dependency tree and execution context, deferring stricter JSX validation until a dedicated compat layer or feature flag is implemented to bridge the runtime object structures.
