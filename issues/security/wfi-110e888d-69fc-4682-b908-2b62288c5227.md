# Mailgun for WordPress <= 2.2.0 - Unauthenticated Server-Side Request Forgery (SSRF) via 'addresses' Array Keys

## Summary

The Mailgun for WordPress plugin (<= 2.2.0) lets unauthenticated users drive requests to arbitrary Mailgun API endpoints. `add_list()` takes array keys from `$_POST['addresses']` and passes them through `sanitize_text_field()`, which does not stop path traversal, so the keys end up in the Mailgun API request path. The request is authenticated with the site's Mailgun API key. Version 2.2.1 fixes it.

## Impact

- **Site owners:** Update to Mailgun for WordPress 2.2.1 or later. Per the advisory, an attacker can create inbound email-forwarding routes that intercept password reset emails, which leads to administrator account takeover.
- **Plugin & theme developers / agencies:** Audit every site running this plugin, including multisite and staging or forked copies. Any code that calls or wraps `add_list()` with user-supplied data should be reviewed.
- **Hosting & platform teams:** The vulnerable path is unauthenticated, so WAF or virtual-patch rules and inventory scans for versions <= 2.2.0 are relevant.
- **After patching:** The source record does not describe exploitation indicators. Sites that were exposed should consider reviewing Mailgun routes and lists for unexpected entries, and rotating the Mailgun API key. This is a precaution, not something the advisory states.

## Technical details

The advisory attributes the flaw to insufficient input validation in `add_list()`. That function accepts user-controlled **array keys** from `$_POST['addresses']` and runs them through `sanitize_text_field()`. That function strips tags and whitespace but does not neutralize path traversal sequences, so an attacker-controlled key can alter the Mailgun API path the plugin requests.

Because the plugin authenticates outbound calls with the site's stored API key, the attacker effectively issues authenticated POSTs to any Mailgun API endpoint. The advisory's example is creating inbound routing rules that forward mail, including password reset messages, to an attacker.

The record does not include the diff or the exact fix in 2.2.1, so the specific validation added is not stated here. The CVSS score is 9.8 (Critical), consistent with a network-reachable, unauthenticated, no-interaction flaw.
