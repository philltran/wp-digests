## Summary

The MountDev AI MCP Connector for WordPress plugin contained a critical authorization bypass that allowed unauthenticated attackers to escalate to administrator-equivalent access. The flaw stemmed from the plugin failing to verify user permissions on its OAuth authorization endpoint, combined with an open Dynamic Client Registration endpoint that accepted arbitrary redirect URIs. Attackers could complete the full OAuth flow without administrator interaction to obtain an admin-bound bearer token, exposing the plugin’s MCP tool surface and underlying WordPress data.

## Impact

- **Plugin administrators**: Must update to the patched version immediately to prevent unauthenticated privilege escalation.
- **Security & hosting teams**: Monitor for OAuth token abuse or unexpected MCP tool calls originating from unauthenticated sources.
- **No code changes required**: The fix is handled server-side by the plugin vendor; simply upgrading the plugin is sufficient.

## Technical details

The vulnerability resides in the plugin’s OAuth implementation, specifically the interaction between the Dynamic Client Registration endpoint and the authorization endpoint. In affected versions, the registration endpoint permitted unauthenticated callers to register arbitrary OAuth clients with attacker-controlled `redirect_uri` values. The authorization endpoint then processed these registrations without verifying that an authenticated administrator had explicitly approved the token request. This allowed an unauthenticated actor to bypass the standard OAuth consent flow, obtain an administrator-bound OAuth Bearer token, and subsequently invoke the plugin’s MCP tool surface with full administrative privileges over exposed WordPress content, users, and options. The patch enforces proper authorization checks on the token issuance path and restricts client registration validation.
