# miniOrange OTP Login, Verification and SMS Notifications <= 5.5.5 - Unauthenticated Authentication Bypass via 'mo_wp_login_intent' Parameter

## Summary

The miniOrange OTP Login, Verification and SMS Notifications plugin allows an unauthenticated attacker to log in as any existing administrator using only a known username, an empty password, and a POST parameter `mo_wp_login_intent=otp`. The flaw is in `mo_by_pass_login()`: in the `skip_pass_fallback`-enabled branch it lacks a password-intent guard and treats administrator role membership as sufficient authentication. It is exploitable only when a specific combination of plugin options is enabled. Version 5.5.6 fixes it.

## Impact

**Site owners**
- Update to 5.5.6 or later. Sites on <= 5.5.5 are exposed to full administrator takeover if all four of these options are enabled together: WP Login OTP, Login with Only OTP, Allow Users to Login with Username and Password, and Admin OTP Bypass.
- If you cannot update immediately, disabling at least one of those four options removes the stated exploit precondition. The advisory does not describe this as an official mitigation, so treat it as a stopgap only.
- On sites that ran an affected version with that configuration, review for unexpected admin logins and sessions, new administrator accounts, and changed plugins or themes. The advisory does not document indicators of compromise.

**Plugin & theme developers / agencies**
- Audit client sites for this plugin and for the option combination above. The CVSS is 9.8 (Critical), but real-world exposure depends on that non-default-looking configuration.
- No API, hook, or data migration changes are described.

**Hosting & platform teams**
- Consider scanning managed fleets for the plugin at <= 5.5.5. Admin usernames are often guessable or enumerable, so the only secret the attacker needs is commonly discoverable.

## Technical details

Per the advisory (no diff or patch is included in the source material):

- **Vulnerable function:** `mo_by_pass_login()`, in the branch where the `skip_pass_fallback` configuration is enabled.
- **Root cause:** a missing password-intent guard. In that branch, administrator role membership alone is treated as sufficient authentication.
- **Trigger:** the unauthenticated, unverified POST parameter `mo_wp_login_intent` set to `otp`. This causes `mo_get_user()` to skip `wp_authenticate_username_password()` and resolve a `WP_User` purely from a username lookup.
- **Request shape:** a login POST with a known administrator username, an empty password, and `mo_wp_login_intent=otp`. No password or OTP verification occurs.
- **Preconditions (all four enabled simultaneously):** WP Login OTP, Login with Only OTP, Allow Users to Login with Username and Password, Admin OTP Bypass.
- **Classification:** CWE-287, Improper Authentication.
- **Fix:** shipped in 5.5.6. The specific code change is not described in the source, so the exact nature of the guard added is unknown.
