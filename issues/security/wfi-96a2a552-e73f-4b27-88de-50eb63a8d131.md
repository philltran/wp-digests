# WPLP Cookie Consent <= 4.4.1 - Unauthenticated Arbitrary File Upload via 'upload-logo' REST Endpoint

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-08-31
- **CVE:** [CVE-2026-75865](https://www.cve.org/CVERecord?id=CVE-2026-75865)
- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-434: Unrestricted Upload of File with Dangerous Type
- **Affected:** WPLP Cookie Consent – Cookie Banner & Consent Management for GDPR, CCPA & Google Consent Mode (plugin) <= 4.4.1
- **Patched in:** 4.4.2
- **Researchers:** Supakiad S. (m3ez)
- **Link:** [https://www.wordfence.com/threat-intel/vulnerabilities/id/96a2a552-e73f-4b27-88de-50eb63a8d131](https://www.wordfence.com/threat-intel/vulnerabilities/id/96a2a552-e73f-4b27-88de-50eb63a8d131)
- **Usefulness:** 5/5

## Summary

WPLP Cookie Consent through 4.4.1 lets unauthenticated attackers upload arbitrary files to the server. `saas_upload_logo()` performs no file type validation, and the plugin's WPLP connector REST endpoints (including `upload-logo`) have an authorization bypass that exposes it to anonymous requests. Uploading an executable file such as PHP may lead to remote code execution. Version 4.4.2 fixes it.

## Impact

**Site owners**
- Update WPLP Cookie Consent to 4.4.2 or later immediately. The flaw is rated critical (CVSS 9.8) and needs no authentication.
- If you ran 4.4.1 or earlier on a public site, check for unexpected files (especially `.php` or other executable types) in the plugin's upload locations and in `wp-content/uploads`, and review access logs for requests to the plugin's `upload-logo` REST route.
- If the plugin cannot be updated right away, deactivate it or block the route at the WAF or web server.

**Plugin & theme developers / agencies**
- Audit client sites and fleet inventories for this plugin and its version.
- This is a reminder that REST routes that accept uploads need a real `permission_callback` and server-side file type validation; neither was sufficient here.

**Hosting & platform teams**
- Consider a fleet-wide scan for the affected version range, and for executable files in upload directories.

**Headless & REST consumers**
- No legitimate client change is needed. The WPLP connector endpoints should not be reachable without proper authorization after the patch.

## Technical details

The advisory names two combined defects. The source record does not include a diff or patch, so only the behaviour described by Wordfence is covered here.

- **Missing file type validation** in `saas_upload_logo()`, the handler behind the `upload-logo` REST endpoint. Nothing restricts the uploaded file to an image type, so dangerous extensions are accepted (CWE-434).
- **Authorization bypass** on the WPLP connector REST endpoints. Unauthenticated callers can reach the upload handler.

Together these allow an anonymous request to write an arbitrary file to the server. Whether that becomes code execution depends on where the file lands and whether the web server will execute it. Fixed in 4.4.2. The record does not describe the specific changes in the patch.
