# WordPress Core <= 7.1 - Forced Theme Install/Preview and Selector Injection via Theme Installer Route

## Summary

WordPress core's theme installer JavaScript (`theme.js`, the `RunInstaller` path) read the `theme` slug from `theme-install.php?theme=<slug>` and inserted it into a jQuery attribute selector without escaping: `$('div[data-slug="'+slug+'"]')`. The selector also matched any matching `div`, not just theme cards. As a result, a crafted URL could make the installer automatically install and preview an inactive WordPress.org theme. It could also inject an arbitrary jQuery selector into the admin page. The fix ships in the listed patched point releases.

## Impact

- **Site owners / administrators:** An attacker can get a logged-in user who can install themes to open a crafted `theme-install.php?theme=...` link. That can trigger an unwanted theme install and preview. The CWE-1021 classification (UI layers/frames) suggests the attack relies on UI redressing or framing. **Action:** update core to a patched release for your branch.
- **Hosting & platform teams:** Make sure managed sites receive the point release. On fleets where auto-updates for minor releases are disabled, push the update manually.
- **Plugin & theme developers:** This is a core-only fix, so no API changes are indicated. As a general lesson, any admin JS that builds jQuery selectors from URL parameters should escape the value, for example with `$.escapeSelector()`, or look elements up with `.filter()` and a data comparison instead of string concatenation.

## Technical details

According to the advisory, there were two problems in the theme installer's `RunInstaller` flow in `theme.js`:

1. **Unescaped selector interpolation.** The `theme` query arg from `theme-install.php` was concatenated directly into a jQuery attribute selector. A value containing `"]` could close the attribute and append an arbitrary selector.
2. **Over-broad match.** The selector targeted any `div[data-slug=...]` instead of only theme card elements. That let the lookup hit unintended DOM elements and drive the auto install/preview behavior.

The vulnerable pattern, as described:

```js
// Before (vulnerable)
$( 'div[data-slug="' + slug + '"]' );
```

The advisory does not include the patched code. It only says the slug was not escaped and the match was not limited to theme cards, so the exact form of the fix is not documented in this record.
