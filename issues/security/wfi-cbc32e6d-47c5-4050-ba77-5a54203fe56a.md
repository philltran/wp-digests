## Summary

User Session Synchronizer's session synchronization handler can be abused by an unauthenticated attacker to impersonate any user, including administrators. The handler trusts attacker-controlled `ussync-key`, `ussync-token`, and `ussync-ref` request parameters without nonce, capability, or shared-secret validation. When an unregistered `ussync-key` is supplied, fallback behavior makes the encryption key and referer check predictable, allowing a crafted `ussync-ref` value to trigger `wp_set_auth_cookie()` for a matched user. No patch is reported, so affected installations should be treated as potentially compromised.

## Impact

- **Site owners / administrators**: If the plugin is installed at or below the affected version, uninstall or disable it immediately; no patch is reported. Review recent authentication events and reset credentials for accounts that may have been impersonated.
- **Plugin & theme developers**: No action required unless the plugin is installed or integrated. If integrating with it, treat its `ussync-*` parameters as untrusted and avoid exposing or forwarding them.
- **Hosting & platform teams**: Block or remove the plugin from affected sites and review authentication logs for unexpected admin logins.
- **Headless & REST consumers**: No direct REST API change is described, but any workflow that depends on the plugin's session synchronization should be suspended while the plugin is removed or replaced.

## Technical details

The vulnerable code path is the `synchronize_session()` function, hooked on `init`, so it runs on every request. It reads the request parameters `ussync-key`, `ussync-token`, and `ussync-ref` and performs no nonce, capability, or shared-secret validation. When `ussync-key` does not correspond to a registered slot, `get_option()` returns `false` for both the secret key and the domain list. That causes the AES-256-CBC encryption key to fall back to `md5('')` and the referer allowlist to collapse to an empty-string match, while the AES IV is hard-coded as `md5('another-secret')`. An attacker can therefore construct a request whose `ussync-ref` value decrypts to a known or guessable user email address; the handler then calls `wp_set_auth_cookie()` for the matched user, granting authentication as that user without prior knowledge of site secrets.
