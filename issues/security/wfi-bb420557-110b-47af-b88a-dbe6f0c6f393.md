# Advanced Customized Prompts <= 1.0.1 - Unauthenticated Privilege Escalation via Account Takeover

- **Type:** Vulnerability
- **Published:** 2026-09-09
- **CVE:** [CVE-2026-14563](https://www.cve.org/CVERecord?id=CVE-2026-14563)
- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-287: Improper Authentication
- **Affected:** Advanced Customized Prompts (plugin) <= 1.0.1
- **Researchers:** 0xBassia
- **Link:** [https://www.wordfence.com/threat-intel/vulnerabilities/id/bb420557-110b-47af-b88a-dbe6f0c6f393](https://www.wordfence.com/threat-intel/vulnerabilities/id/bb420557-110b-47af-b88a-dbe6f0c6f393)
- **Usefulness:** 5/5

## Summary

The Advanced Customized Prompts plugin (<= 1.0.1) authenticates users without verifying their password. An unauthenticated attacker can log in as any existing user, including administrators, resulting in full account takeover. No patched version is available.

## Impact

- **Site owners:**
  - Any site running Advanced Customized Prompts <= 1.0.1 is exposed to unauthenticated administrator takeover, which typically leads to full site compromise (plugin/theme upload, arbitrary code execution, data access).
  - There is no known patch. The advisory suggests uninstalling the plugin and finding a replacement, or applying mitigations based on your risk tolerance.
  - Sites that have run the plugin should audit for unexpected logins, newly created administrator accounts, and unfamiliar plugins, themes, or file changes.
- **Plugin & theme developers / agencies:** Inventory client sites for this plugin. Deactivate and remove it where possible, and consider rotating credentials and sessions on affected sites.
- **Hosting & platform teams:** Consider blocking or virtual-patching the plugin's authentication entry point if you can identify it. Flag installs of this plugin fleet-wide.
- **Headless & REST consumers:** If the login path is reachable via REST or AJAX, sessions or application credentials could be obtained by an attacker. The record does not say which endpoint is involved.

## Technical details

The record classifies this as CWE-287 (Improper Authentication), CVSS 9.8. The stated root cause is that the plugin does not verify a user's password before authenticating them, so a request identifying a target user is enough to establish a session as that user.

The advisory does not name the vulnerable function, hook, endpoint, or file, and no diff or patch is available, so the exact code path (for example an AJAX action, REST route, or a direct `wp_set_auth_cookie()`/`wp_set_current_user()` call) cannot be confirmed from this record. Do not assume a specific mechanism.
