# Sigma Forms Pro <= 1.4.5 - Unauthenticated Unauthenticated Arbitrary File Upload Leading to Remote Code Execution via Pre-built Template File Upload Field

## Summary

Sigma Forms Pro (SigmaForms Pro – AI Generated Forms) up to 1.4.5 lets unauthenticated attackers upload arbitrary files, including PHP, through form submissions. `handle_form_submission` dynamically grants the `unfiltered_upload` capability to all users during submission and skips MIME type validation when a file field has no `allowed_file_types` configured. Several default pre-built templates ship with unrestricted file upload fields, so the flaw is exploitable on a fresh install. Version 1.4.6 fixes it.

## Impact

**Site owners**
- Any site running Sigma Forms Pro <= 1.4.5 is exposed to unauthenticated remote code execution. Update to 1.4.6 or later immediately.
- Sites that used the pre-built Job Application, Support Ticket, or Wholesale Application templates are exploitable by default, since those templates have file upload fields with no file type restrictions.
- Sites with custom forms are also affected if any file upload field lacks `allowed_file_types`.
- Patching does not remove files already uploaded. Review the uploads directory for unexpected `.php` or other executable files, and check for signs of compromise on any site that ran an affected version with a public form.

**Plugin & theme developers / agencies**
- Audit client sites for this plugin, especially those built from the pre-built templates.
- No API deprecations or code migrations are described in the record.

**Hosting & platform teams**
- Consider WAF rules or blocking PHP execution in the uploads directory as defense in depth, and look for anomalous submissions to the plugin's form handler on unpatched sites.

## Technical details

The record describes two combined flaws in `handle_form_submission`:

1. **Capability escalation:** the function dynamically grants `unfiltered_upload` to all users, including unauthenticated visitors, for the duration of form submission handling. This removes WordPress core's normal restriction on dangerous file types.
2. **Validation bypass:** when a field's `allowed_file_types` is not configured, MIME type validation is skipped entirely.

Several default pre-built templates (Job Application, Support Ticket, Wholesale Application) define file upload fields with no `allowed_file_types`, so both conditions hold out of the box. An attacker can upload an executable file such as PHP and run code on the server (CWE-434).

The source record does not include a diff or describe the specific changes in 1.4.6, so the exact fix is not documented here.
