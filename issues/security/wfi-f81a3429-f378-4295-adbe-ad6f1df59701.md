# Podlove Podcast Publisher <= 4.5.1 - Unauthenticated Arbitrary File Upload via podlove_image_cache_url Parameter

## Summary

Podlove Podcast Publisher versions up to 4.5.1 contain an unauthenticated arbitrary file upload vulnerability in the `podlove_handle_cache_files` function. The flaw stems from missing file type validation on the `podlove_image_cache_url` parameter, allowing attackers to upload arbitrary files to the server. This can lead to remote code execution and requires immediate patching to version 4.5.2 or later.

## Impact

- **Plugin users & site owners:** All sites running Podlove Podcast Publisher ≤ 4.5.1 are exposed to unauthenticated file uploads. Update to ≥ 4.5.2 immediately.
- **Hosting & platform teams:** Monitor for suspicious file uploads to the plugin’s cache directory and ensure WAF rules block requests to the vulnerable endpoint.
- **No action required** for sites that have already updated or do not use this plugin.

## Technical details

The vulnerability resides in the `podlove_handle_cache_files` function, which processes the `podlove_image_cache_url` parameter without validating the uploaded file’s MIME type or extension. An unauthenticated attacker can craft a request to this endpoint and bypass the intended image caching logic to write arbitrary files to the server filesystem. Patched in 4.5.2, the fix introduces proper file type validation before processing the cache request. Developers should verify that their `wp-content/uploads` or plugin cache directories are not world-writable and consider restricting direct execution of uploaded assets via server configuration until the update is applied.
