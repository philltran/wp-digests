## Summary

WPFunnels contained a critical unauthenticated remote code execution vulnerability triggered via the `postData` parameter. Attackers could inject arbitrary PHP code into a `.log` file through an unsanitized write, which was then executed via `include_once` in the `wpfnl_show_log` function. The plugin has been patched to sanitize input and prevent arbitrary file inclusion, eliminating the execution path.

## Impact

- **Site owners & WooCommerce merchants**: Update WPFunnels to the patched version immediately to prevent server compromise.
- **Plugin & theme developers**: No direct API changes, but audit custom integrations that interact with the plugin's logging or funnel step endpoints.
- **Hosting & platform teams**: Monitor for anomalous `include_once` calls targeting WPFunnels log files and ensure server-side WAF rules block `postData` payloads containing PHP execution sequences.
- **No action required** beyond updating the plugin to the patched release.

## Technical details

The vulnerability stemmed from an unsanitized write of the `postData` parameter into a `.log` file, followed by an `include_once` of that file inside `wpfnl_show_log`. Although exploitation required the "Enable Logs" toggle to be active and an administrator to view the log in the UI, the nonce protecting the optin endpoint was publicly rendered on every funnel step page, allowing unauthenticated injection. The patch resolves the chain by enforcing strict sanitization on the `postData` write path and removing the direct `include_once` execution of user-controlled log files.
