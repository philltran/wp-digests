# Eventer <= 4.4.2 - Insecure Password Reset Mechanism to Unauthenticated Privilege Escalation

- **Type:** Vulnerability
- **Published:** 2026-07-07

- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-289: Authentication Bypass by Alternate Name
- **Affected:** Eventer (plugin) <= 4.4.2
- **Researchers:** Rafie Muhammad
- **Link:** [https://www.wordfence.com/threat-intel/vulnerabilities/id/bc656765-1eac-4a96-99e9-c22d64984923](https://www.wordfence.com/threat-intel/vulnerabilities/id/bc656765-1eac-4a96-99e9-c22d64984923)
- **Usefulness:** 5/5

## Summary

The Eventer plugin (≤4.4.2) contains a critical authentication bypass that allows unauthenticated attackers to reset any user’s password. The flaw occurs because the plugin stores the password reset token in plaintext within the `eventer_verification_code` user meta field, which can then be submitted to the plugin’s custom reset action to hijack accounts. This vulnerability is especially dangerous when chained with SQL injection flaws, as it enables full privilege escalation to administrator accounts.

## Impact

- **Site owners & administrators**: All installations of Eventer ≤4.4.2 are vulnerable to account takeover. No patch is currently available; immediate mitigation or plugin removal is required.
- **Hosting & platform teams**: The exploit chain is constrained to PHP ≤7.4 due to how the reset handler processes requests. PHP 8+ environments are not affected by this specific reset flow, though the plugin remains unpatched.
- **Action required**: Disable or uninstall Eventer immediately, or implement a custom password reset override that does not rely on the vulnerable meta field.

## Technical details

The vulnerability resides in Eventer’s custom password reset workflow. When a reset is requested, the plugin writes the generated reset token directly to the `eventer_verification_code` user meta key in `wp_usermeta` without hashing or expiration safeguards. An attacker can query this meta value (or extract it via the companion SQL injection in CVE-2026-9700) and submit it to the plugin’s custom reset action to force a password change for any user ID. The exploit is only functional on PHP ≤7.4. No patch has been released, and the vendor has not published a fixed version.
