## Summary

The WooCommerce Social Login plugin (≤2.8.7) contained a critical authentication bypass that allowed unauthenticated attackers to log in as any existing WordPress user, including administrators. The vulnerability stemmed from the Apple login handler accepting a forged `id_token` JWT without verifying its cryptographic signature or validating standard claims like issuer, audience, and expiry. Because the handler resolved users solely by the email address in the decoded payload, attackers could craft a token with an admin’s email to hijack sessions. Updating to 2.8.8 is required to restore secure OAuth/JWT validation.

## Impact

- **Site owners & administrators**: Unauthenticated attackers could bypass login entirely and assume any existing user role, including admin. Immediate update to 2.8.8 is required.
- **Plugin & theme developers**: No direct API changes, but developers integrating custom Apple OAuth flows should audit their own JWT validation logic to ensure signatures, `iss`, `aud`, and `exp` claims are verified.
- **Hosting & platform teams**: Monitor for anomalous login attempts or session creation via the Apple social login endpoint. No configuration changes needed beyond applying the plugin update.

## Technical details

The vulnerability resided in the Apple OAuth handler, which extracted the `id_token` from the login request and decoded only its base64 payload to retrieve the user’s email address. It skipped JWT signature verification against Apple’s public keys and omitted validation of the `iss`, `aud`, and `exp` claims. Additionally, the nonce required to trigger the login flow was exposed to unauthenticated users via a localized JavaScript object, removing the CSRF protection layer. The fix in 2.8.8 enforces standard JWT verification: validating the cryptographic signature, checking claim expiration, and ensuring the issuer and audience match Apple’s expected values before resolving the WordPress user by email.
