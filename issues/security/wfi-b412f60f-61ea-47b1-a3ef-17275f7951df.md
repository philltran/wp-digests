## Summary

The SAML Single Sign On – SSO Login plugin (≤5.4.4) contained a critical authentication bypass vulnerability. A loose boolean evaluation of `openssl_verify()` in `mo_saml_validate_signature()` incorrectly treated OpenSSL error returns (-1) as successful signature verification. This allowed unauthenticated attackers to forge SAML responses, bypass cryptographic checks, and log in as any existing WordPress user, including administrators. The issue is resolved in version 5.4.5.

## Impact

- **Site owners & administrators:** Must update the SAML Single Sign On – SSO Login plugin to 5.4.5 or later immediately to prevent unauthenticated account takeover.
- **Plugin & theme developers:** No direct code changes required, but developers integrating SAML/SSO should audit their own signature validation logic to ensure strict integer comparison against `openssl_verify()` return values.
- **Hosting & platform teams:** Monitor for exploitation attempts targeting the `SAMLResponse` parameter and ensure plugin update pipelines are configured to catch this critical patch.
- **Required action:** Update to ≥5.4.5. No migration or configuration changes needed.

## Technical details

The vulnerability stems from `mo_saml_validate_signature()` evaluating the return value of PHP's `openssl_verify()` with a loose truthiness check. `openssl_verify()` returns `1` on success, `0` on failure, and `-1` on an internal OpenSSL error. The flawed logic treated `-1` as truthy, effectively skipping signature verification. The fix enforces a strict equality check against `1`, ensuring that both verification failures and OpenSSL processing errors halt the authentication flow. Attackers previously exploited this by submitting a malformed `SAMLResponse` with a crafted `NameID` and invalid signature bytes, triggering the `-1` error path and allowing `wp_set_auth_cookie()` to execute without cryptographic validation.

```php
// Before (vulnerable pattern)
if ( openssl_verify( $data, $signature, $public_key ) ) {
    // -1 (error) evaluates as truthy, bypassing verification
}

// After (patched pattern)
if ( openssl_verify( $data, $signature, $public_key ) === 1 ) {
    // Only success (1) proceeds; 0 and -1 are rejected
}
```
