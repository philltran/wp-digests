# TrueBooker <= 1.2.3 - Missing Authorization to Unauthenticated Arbitrary Password Reset via 'tbab-userid'

- **Usefulness:** 5/5

## Summary

TrueBooker <= 1.2.3 allowed unauthenticated attackers to reset arbitrary user passwords by supplying a `tbab-userid` value without proving ownership of the target account. The plugin failed to validate the user's identity before performing the password reset, enabling account takeover, including administrator accounts. Version 1.2.4 fixes the improper password reset validation.

## Impact

- **Site owners**: Update TrueBooker to 1.2.4 or newer immediately. If the plugin was exposed while <= 1.2.3, review recent account changes and rotate credentials for affected accounts, especially administrators.
- **Plugin and theme developers**: No direct code change is required unless you integrate with TrueBooker. If you build similar booking or account flows, ensure password reset endpoints require authenticated or tokenized ownership validation.
- **Hosting and platform teams**: Scan for TrueBooker <= 1.2.3 and force updates. Monitor for unauthenticated password reset requests targeting `tbab-userid`.
- **Headless and REST consumers**: No API contract change is described in the record. No action required.

## Technical details

The advisory identifies the vulnerable input as `tbab-userid`. The plugin accepted a user identifier and performed a password reset without proper authorization or identity validation. This allowed an unauthenticated attacker to reset the password of an arbitrary account. The record does not name a specific file, function, hook, REST route, or database change; it describes the fix in 1.2.4 as correcting improper password reset validation.
