# WordPress Core 6.8 -  7.0.1 - Unauthenticated SQL Injection via author__not_in Parameter

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-07-17
- **CVE:** [CVE-2026-60137](https://www.cve.org/CVERecord?id=CVE-2026-60137)
- **CVSS:** 7.5 (High)
- **CWE:** CWE-89: Improper Neutralization of Special Elements used in an SQL Command ('SQL Injection')
- **Affected:** WordPress (core) >= 6.8 and < 6.8.5; >= 6.9 and < 6.9.5; >= 7.0 and < 7.0.2
- **Patched in:** 6.8.6, 6.9.5, 7.0.2
- **Researchers:** Tin Pham (TF1T), Trong Pham (dtro), haongo

- **Usefulness:** 5/5

## Summary

WordPress core contains an unauthenticated SQL injection vulnerability triggered through the `author__not_in` query parameter, present in versions 6.8 through 7.0.1. The parameter was insufficiently escaped and the underlying SQL query insufficiently prepared, letting an attacker append arbitrary SQL to an existing query. Because no authentication is required to reach the vulnerable code path, any public-facing site running an affected version could have its database queried for sensitive data by an anonymous attacker. The issue is fixed in 6.8.6, 6.9.5, and 7.0.2.

## Impact

- **Site owners:** Update immediately — this is unauthenticated and remotely exploitable, so exposure doesn't depend on user roles, plugins, or login access; any site on 6.8–7.0.1 is at risk until patched.
- **Plugin/theme developers:** If custom code builds `WP_Query`, `WP_Comment_Query`, or `WP_User_Query` calls that pass request input straight into `author__not_in` (or otherwise route unsanitized values into the same clause-building path), review and re-test after updating — don't assume core's fix compensates for input you're forwarding unescaped from your own code.
- **Hosting/platform teams:** Push the core update across managed fleets; sites pinned to non-updating configurations on the affected 6.8.x/6.9.x/7.0.x lines need explicit remediation. A WAF rule targeting this parameter (e.g. from Wordfence) can provide interim mitigation before patching.
- **Headless & REST consumers:** Any custom REST route or endpoint that accepts and forwards an `author__not_in`-style value to a WP_Query-based lookup was a plausible exploitation surface for unauthenticated callers — audit such endpoints after patching.

## Technical details

The `author__not_in` argument (supported by `WP_Query` and related query classes to exclude posts/content by author ID) is used to build a `post_author NOT IN (...)` SQL clause. The advisory states the values passed through this parameter were not adequately escaped and the query built from them was not properly prepared, classifying it as CWE-89 (SQL Injection). This allowed an attacker to break out of the intended `NOT IN` list and append additional SQL to the query, exfiltrating data via a classic UNION/boolean/error-based injection pattern. The published advisory does not include a diff, so the exact file/function touched by the fix (presumably tightening `$wpdb->prepare()` usage or casting/whitelisting the author ID list before interpolation) isn't specified here — only that the fix ships in 6.8.6, 6.9.5, and 7.0.2.
