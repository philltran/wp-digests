# Automation Web Platform <= 4.8.6 - Unauthenticated Authentication Bypass via 'otp_transient' Token Disclosure

## Summary

The Automation Web Platform plugin (Notifications and OTP for WooCommerce, Advanced Country Code) through 4.8.6 leaks its secret magic login token in the response to a publicly accessible OTP request. `handle_email_otp_return()` returns the token to the caller instead of delivering it only to the user's email address. An unauthenticated attacker who knows a user's email address can log in as that user, including an administrator. Version 4.8.7 fixes it.

## Impact

**Site owners**
- Any site running the plugin at <= 4.8.6 is exposed to full unauthenticated account takeover, including administrator accounts, needing only a known or guessable email address.
- Update to 4.8.7 or later immediately.
- If the site was exposed, review administrator accounts, recently created users, and sessions for signs of compromise. Consider forcing logout of all sessions and rotating credentials. The source record does not describe indicators of compromise, so this is general precaution.

**Plugin & theme developers / agencies**
- Audit client sites and managed fleets for this plugin and patch them.
- If you run custom code that depends on this plugin's OTP flow, retest after updating, since the response no longer carries the token.

**Hosting & platform**
- Consider a virtual patch or WAF rule if fleet-wide updates will lag. The source does not specify the exact endpoint, so any rule would need to be derived from the plugin code.

**Headless & REST consumers**
- The source does not say whether the OTP request is an AJAX action or REST route. Verify any integration that consumes the OTP response against 4.8.7.

## Technical details

The record describes a CWE-640 (weak password recovery mechanism) flaw. `handle_email_otp_return()` handles a publicly accessible OTP request. It includes the secret magic login token (`otp_transient`) in the response, when it should only send that token to the user's email address. The token is the credential that authenticates the login, so anyone who triggers the OTP request for a target email receives it directly and can complete the login without having access to the mailbox.

The fix shipped in 4.8.7. The source record contains no diff or patch details, so the exact change (for example, removing the token from the response) is not confirmed here. No hooks, REST schema, or database changes are described.
