## Summary

The Admin and Site Enhancements (ASE) Pro plugin contained an unauthenticated remote code execution vulnerability in versions up to 8.9.0. The flaw allowed attackers to inject arbitrary PHP code via the `cfgroup[input]` repeater row key, which was passed unsanitized into an `eval()` call inside the `recursive_html` function. The vulnerability required the `[post_cf_form]` shortcode to be present on a public page to emit the necessary nonce and session ID. Patched in version 8.9.1, this fix eliminates a critical server-side execution risk for sites using the plugin's form builder.

## Impact

- **Site owners & plugin developers:** Sites running ASE Pro ≤ 8.9.0 with the `[post_cf_form]` shortcode on public pages are immediately vulnerable to unauthenticated RCE. Update to 8.9.1 or later without delay.
- **Hosting & platform teams:** Monitor for anomalous `eval()` execution or unexpected PHP processes originating from WordPress cron or frontend requests. No configuration changes are needed beyond the plugin update.
- **No action required** for sites that do not use ASE Pro or do not have the `[post_cf_form]` shortcode rendered publicly.

## Technical details

The frontend save handler for `[post_cf_form]` previously validated only a publicly emitted nonce, skipped authentication, and allowed CAPTCHA bypass by omitting a key. Repeater row keys from `cfgroup[input]` were stored verbatim and interpolated into an `eval()` call inside `recursive_html` without sanitization or identifier validation. The 8.9.1 patch enforces authentication and CAPTCHA on the save handler, validates row keys against a strict identifier pattern, and sanitizes input before evaluation.

**Before:** `cfgroup[input]` row keys passed unsanitized to `eval()` in `recursive_html`.
**After:** Row keys are validated against a strict identifier pattern and sanitized before reaching `eval()`, and the save handler requires authentication/CAPTCHA.
