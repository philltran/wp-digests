# WPMU DEV Dashboard <= 5.0.1 - Authentication Bypass to Administrator via SSO HMAC Canonicalization Confusion

## Summary

The WPMU DEV Dashboard plugin's Hub SSO flow builds its HMAC over inconsistent messages in its two unauthenticated AJAX steps. `wdpsso_step1` signs and discloses an unseparated concatenation of token, state, redirect, and domain. `wdpsso_step2` verifies an unseparated concatenation that omits domain. An unauthenticated attacker can take a valid HMAC from step 1 and replay it to step 2, which yields an authenticated administrator session. Version 5.0.2 fixes it.

## Technical details

The flaw is a signature-verification error (CWE-347) caused by canonicalization confusion in the HMAC message.

- `wdpsso_step1` computes an HMAC over the unseparated concatenation of `token`, `state`, `redirect`, and `domain`, and discloses the result to the unauthenticated caller.
- `wdpsso_step2` verifies an HMAC over the unseparated concatenation of `token`, `state`, and `redirect`, omitting `domain`.
- Because there are no delimiters and step 2 leaves out `domain`, the same concatenated string can be produced from different field splits. An attacker obtains a valid HMAC from step 1, then submits it to step 2 with the `domain` value moved into the `redirect` field. The message step 2 reconstructs is byte-identical to what step 1 signed, so the check passes and an administrator session is issued.

The preconditions are that the site is connected to WPMU DEV and Hub SSO is enabled and mapped to an administrator.

The record does not include the patch diff, so how 5.0.2 changes the construction is not documented in the source. The conventional fixes would be a consistent field set on both sides and unambiguous encoding, but that is not confirmed here.
