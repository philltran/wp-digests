## Summary

The miniOrange Social Login and Register plugin (≤7.7.0) contained a critical authentication bypass in its profile completion flow that allowed unauthenticated attackers to take over administrator accounts. The vulnerability stemmed from accepting an arbitrary email address via the `email_field` POST parameter without validating it against the OAuth provider, combined with a weak OTP generation and hash leakage that enabled offline cracking. Version 7.8.0 patches this by enforcing email verification against the authenticated identity and hardening the OTP validation logic.

## Impact

- **Site owners & administrators**: Must update to version 7.8.0 immediately to prevent unauthenticated account takeover.
- **Plugin & theme developers**: No direct API changes or deprecations; however, any custom integrations relying on the plugin's profile completion flow should verify they are not bypassing the new validation.
- **Hosting & platform teams**: Monitor for exploitation attempts targeting the `email_field` parameter and enforce automated plugin update policies.
- **No backward-incompatible changes**: This is a security patch that maintains existing functionality while closing the authentication gap.

## Technical details

The vulnerability existed in the profile completion workflow where `send_otp_token()` returned a SHA-512 hash of `customer_key || otp` to the client. Because `customer_key` defaults to an empty static option and the OTP was generated via `wp_rand(1000, 99999)`, the 99,000-value space could be brute-forced offline in under a second. Attackers could supply any email via the `email_field` POST parameter, trigger the OTP email, crack the hash, and submit it to `mo_openid_social_login_validate_otp()` to authenticate as that user. The 7.8.0 patch resolves this by validating the submitted email against the OAuth provider's returned identity and securing the OTP generation/validation flow to prevent hash leakage and offline cracking.
