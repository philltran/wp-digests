## Summary

The Cost Calculator Builder PRO plugin contained a critical unauthenticated remote code execution vulnerability in versions up to 4.0.3. Attackers could exploit the `js_to_php` function by injecting malicious payloads into the `orderDetails[*].originalValue` field, which was passed directly to `PHP eval()` without proper sanitization. The vulnerability was patched in version 4.0.4, and all affected sites must update immediately to prevent server compromise.

## Impact

- **Plugin users (site owners & agencies):** All installations running Cost Calculator Builder PRO ≤ 4.0.3 are at immediate risk of unauthenticated RCE. Update to ≥ 4.0.4.
- **Hosting & platform teams:** Monitor for anomalous `eval()` execution patterns or calculator form submissions containing non-word XOR gadgets; consider temporary WAF rules blocking `orderDetails` payloads.
- **No action required** for sites that have already updated to 4.0.4+ or do not use this plugin.

## Technical details

The vulnerability resides in the plugin's `js_to_php` function, which accepts the `orderDetails[*].originalValue` parameter from front-end form submissions. This value is injected verbatim into a calculator formula string and passed to `PHP eval()`. The existing sanitization in `evaluateFormula()` relies on a regex allow-list that only strips alphanumeric tokens, leaving non-word punctuation characters intact. Because the required nonce is output globally via `wp_head`, unauthenticated attackers can freely obtain it and bypass the authentication barrier. Patched versions properly sanitize or escape the `originalValue` field before evaluation, eliminating the code injection vector.
