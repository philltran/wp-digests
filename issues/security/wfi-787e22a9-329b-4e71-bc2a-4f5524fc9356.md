# Gravity Forms <= 3.1.0.4 - Unauthenticated Arbitrary File Upload via Hidden File Upload Field

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-09-18
- **CVE:** [CVE-2026-84434](https://www.cve.org/CVERecord?id=CVE-2026-84434)
- **CVSS:** 9.8 (Critical)

- **Affected:** Gravity Forms (plugin) <= 3.1.0.4
- **Patched in:** 3.1.1
- **Researchers:** 0xd4rk5id3

- **Usefulness:** 5/5

## Summary

Gravity Forms up to and including 3.1.0.4 allows unauthenticated arbitrary file upload. A File Upload field with Visibility set to 'Hidden' skips extension validation, and a file that was rejected still carries its intact upload state into `upload_file()`, which persists it without re-validation. Files that may be executable can land on the server, making remote code execution possible. Version 3.1.1 fixes it.

## Impact

**Site owners**
- Any publicly accessible form containing a File Upload field with Visibility set to 'Hidden' is exploitable by unauthenticated attackers. Forms without such a field are not reachable through this path.
- Update Gravity Forms to 3.1.1 or later. The advisory's CVSS is 9.8 (Critical).
- Until patched, audit forms for File Upload fields set to Hidden and change their visibility or unpublish the form.
- Review the Gravity Forms upload directory for unexpected executable files (e.g. `.php`) that could indicate prior exploitation. The advisory does not describe indicators of compromise, so this is a general precaution.

**Plugin & theme developers / agencies**
- Add 3.1.1 to your update rollout across client sites. Hidden upload fields are an unusual configuration, so check for them, but do not treat their absence as a reason to delay the update.
- No API, hook, or configuration change is described in the advisory.

**Hosting & platform**
- Blocking execution of scripts in the Gravity Forms upload directory is a reasonable defense-in-depth measure. The advisory does not state whether this fully mitigates the issue.

## Technical details

The advisory attributes the flaw to a mismatch between two pipelines in Gravity Forms:

1. **Field validation pipeline:** for File Upload fields with Visibility set to 'Hidden', extension validation is bypassed.
2. **File persistence pipeline:** a file that was rejected still has its upload state intact, and that state is later passed to `upload_file()` without re-validation.

Combined, an attacker can submit a file with a disallowed (potentially executable) extension to a form with a hidden upload field. Validation does not stop it, and `upload_file()` writes it to disk. The weakness is classified as unrestricted upload of a file with a dangerous type.

No patch diff or code from 3.1.1 is included in the source record, so the exact fix (for example, re-validating inside `upload_file()` or enforcing validation regardless of field visibility) is not confirmed here.
