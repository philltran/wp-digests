# Advanced Custom Fields: Extended PRO <= 0.9.2.6 - Unauthenticated Remote Code Execution via Dynamic Render Field Type

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-09-14
- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-434: Unrestricted Upload of File with Dangerous Type
- **Affected:** Advanced Custom Fields: Extended PRO (plugin) <= 0.9.2.6
- **Patched in:** 0.9.2.7
- **Researchers:** Tin Pham (TF1T), Trong Pham (dtro), Hao Ngo

- **Usefulness:** 5/5

## Summary

Advanced Custom Fields: Extended PRO up to and including 0.9.2.6 lets unauthenticated attackers reach a `call_user_func_array` sink in its `render_field` method. Form configuration parameters are merged into field settings without sufficient validation, so an attacker can call arbitrary WordPress functions with attacker-controlled arguments. Version 0.9.2.7 fixes it.

## Impact

**Site owners**
- Update Advanced Custom Fields: Extended PRO to 0.9.2.7 or newer. The issue is rated CVSS 9.8 and requires no authentication.
- Exploitation depends on one of two conditions, so not every install is equally exposed:
  - **Method 1:** an administrator has enabled the non-default `shortcode_preview` setting for the target form.
  - **Method 2:** the server's PHP lacks OpenSSL functions, which makes ACF Pro's `acf_decrypt` fall back to unverified base64 decoding.
- Until patched, check whether any form has `shortcode_preview` enabled and whether OpenSSL is available in PHP. Disabling the setting removes Method 1 only. It does not address Method 2.

**Plugin & theme developers**
- If your code depends on this plugin's form rendering, retest forms after updating.

**Hosting & platform teams**
- Hosts running PHP without the OpenSSL extension are exposed through Method 2 regardless of plugin settings. Consider scanning fleets for the plugin at <= 0.9.2.6.

The advisory does not describe a migration or a breaking change in 0.9.2.7.

## Technical details

The advisory places the flaw in the plugin's `render_field` method. Form configuration parameters are merged into field settings without adequate validation, and the resulting values are passed to `call_user_func_array`. This lets an attacker choose which WordPress function is called and what arguments it receives. Wordfence classifies this as "Limited Code Injection" (arbitrary function calls with controlled arguments) and maps it to CWE-434.

Two routes are described:

1. **`shortcode_preview` route:** the target form must have this non-default setting enabled by an administrator.
2. **Weak `acf_decrypt` route:** ACF Pro's `acf_decrypt` falls back to unverified base64 decoding when OpenSSL functions are unavailable. The advisory implies attacker-supplied configuration is accepted without integrity verification in that case.

The advisory does not include the patch diff, so the exact 0.9.2.7 changes (allowlisting, signature checks, etc.) are not described here.
