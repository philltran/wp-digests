# Link Library <= 7.9.4 - Unauthenticated Arbitrary File Deletion via link_url Parameter

## Summary

Link Library's link-deletion routine accepted an unvalidated file path from the `link_url` parameter, allowing unauthenticated arbitrary file deletion when the optional local-file deletion setting was enabled and an administrator permanently deleted a submitted link. The vulnerability can lead to remote code execution if a critical file such as `wp-config.php` is deleted. The patched release corrects the path validation in the deletion flow.

## Impact

- **Site owners:** Update Link Library to the patched release. If the 'Delete local file on link deletion' option is enabled, treat this as urgent; if immediate update is not possible, disable that option and review recent link deletions.
- **Plugin & theme developers:** No public API change is described, but any integration that relies on Link Library's local-file deletion behavior should be retested after updating.
- **Hosting & platform teams:** Patch or isolate affected sites, especially where the optional local-file deletion setting is enabled.
- **Headless & REST consumers:** No REST route or schema change is described in the record.

## Technical details

The vulnerable behavior is in `ll_delete_link_fields`, where the `link_url` value was used to delete a local file without sufficient path validation. An attacker could submit a link whose `link_url` pointed to an arbitrary server path; if the administrator enabled 'Delete local file on link deletion' and permanently deleted that link, the plugin deleted the target file. The patched release addresses the insufficient file path validation so arbitrary files cannot be removed through this parameter. The record does not include the exact code diff.
