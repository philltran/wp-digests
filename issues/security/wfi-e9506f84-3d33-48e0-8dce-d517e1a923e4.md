# Meta Box AIO <= 3.8.0 - Missing Authorization to Unauthenticated Arbitrary Post Deletion via 'rwmb_frontend_field_object_id' Parameter

## Summary

Meta Box AIO versions up to 3.8.0 contain a critical missing-authorization vulnerability in the MB Frontend Submission extension that allows unauthenticated attackers to delete arbitrary posts and pages. The flaw occurs because the `handle_request()` function processes the `mbfs_delete` action without verifying user capabilities or post ownership, and the nonce check is bypassed when requests arrive via `template_redirect` instead of AJAX. Site owners must update to version 3.9.0 or later to prevent unauthorized content deletion.

## Impact

- **Site owners & administrators:** Unauthenticated visitors can permanently delete any post or page on the site by targeting a URL containing a frontend submission form. Immediate update to Meta Box AIO 3.9.0+ is required.
- **Plugin & theme developers:** No code changes needed if updating the plugin, but developers embedding frontend submission forms should audit custom implementations to ensure they enforce `allow_delete` flags and capability checks.
- **Hosting & platform teams:** Monitor for anomalous `rwmb_frontend_field_object_id` GET parameters in server logs and ensure patching pipelines prioritize this critical update.

## Technical details

The vulnerability resides in the `handle_request()` method of the MB Frontend Submission extension, which dispatches the `mbfs_delete` action during the `template_redirect` lifecycle. Unlike standard AJAX submissions, `template_redirect` requests bypass the `check_ajax()` nonce verification because that check is strictly gated behind `is_ajax()`. Consequently, an attacker can trigger post deletion by appending `?rwmb_frontend_field_object_id=<post_id>` to any page rendering a frontend submission form, completely ignoring the `allow_delete` configuration flag.
