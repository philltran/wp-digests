# Teddy Bear Customize Addon <= 1.0.5 - Unauthenticated Privilege Escalation via Account Takeover

- **Type:** Vulnerability

- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-269: Improper Privilege Management
- **Affected:** Teddy Bear Customize Addon (plugin) <= 1.0.5
- **Researchers:** 0xBassia
- **Link:** [https://www.wordfence.com/threat-intel/vulnerabilities/id/677a9713-e7c6-477d-9ba9-8b0e2bdb2c6d](https://www.wordfence.com/threat-intel/vulnerabilities/id/677a9713-e7c6-477d-9ba9-8b0e2bdb2c6d)
- **Usefulness:** 5/5

## Summary

The Teddy Bear Customize Addon plugin, in all versions up to and including 1.0.5, authenticates users without verifying their password. An unauthenticated attacker can log in as any other user, including administrators, resulting in full account takeover. No patched version exists.

## Impact

- **Site owners:**
  - Any site running Teddy Bear Customize Addon <= 1.0.5 is exposed to unauthenticated administrator account takeover (CVSS 9.8).
  - No patch is available. Per the advisory, the safest option is to deactivate and uninstall the plugin and find a replacement.
  - If the plugin was active, treat the site as potentially compromised: audit administrator accounts, recently created users, installed plugins/themes, and file changes, and rotate credentials and salts.
- **Plugin & theme developers / agencies:**
  - Inventory client sites for this plugin (e.g. `wp plugin list --name=<slug>` across fleets). Confirm the exact slug from the plugin directory listing rather than assuming it.
  - If removal is not immediately possible, block access at the WAF or host level, but the source record does not describe the vulnerable entry point, so specific rules cannot be derived from it.
- **Hosting & platform teams:**
  - Consider fleet-wide scanning for the affected plugin and forced deactivation given the unauthenticated, critical nature and the absence of a fix.
- **Headless & REST consumers:** The record does not say whether the flaw is reachable via REST, AJAX, or another route, so no route-specific guidance can be given.

## Technical details

The advisory states only that the plugin does not verify a user's password before authenticating. This allows an unauthenticated request to log in as an arbitrary existing user, which is classified as CWE-269 (Improper Privilege Management).

The source record does not name the vulnerable function, hook, file, or endpoint, and no code or diff is provided, so the exact mechanism (for example, which login or authentication handler is involved) cannot be stated here. No fixed version exists: the affected range is <= 1.0.5 with no known patch.
