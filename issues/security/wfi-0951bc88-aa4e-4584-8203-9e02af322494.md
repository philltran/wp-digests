# Meta Box AIO <= 3.7.2 And Standalone Plugin Extensions - Unauthenticated Privilege Escalation to Administrator to 'rwmb_frontend_field_object_id' Parameter

- **CWE:** CWE-269: Improper Privilege Management
- **Affected:** Meta Box User Profile (plugin) <= 3.11.0, Meta Box AIO (plugin) <= 3.11.0, Meta Box Frontend Submission (plugin) <= 4.5.6

- **Usefulness:** 5/5

## Summary

Meta Box AIO and its standalone extensions contain a chained flaw that lets an unauthenticated attacker become an Administrator. `populate_via_query_string()` in the mb-frontend-submission component accepts the `rwmb_frontend_field_object_id` GET parameter and overrides the form's target `object_id` with no authorization check. Because `Form::process()` lacks the `user_can_edit()` check that `render()` has, the attacker can overwrite the `post_content` of any page with an arbitrary shortcode. The injected `[mb_user_profile_register]` shortcode is then trusted by mb-user-profile, which honors its `role` and `auto_login` attributes without validation. Fixes shipped in 3.12.0 (AIO / User Profile) and 4.6.0 (Frontend Submission).

## Impact

**Site owners**
- Any site running an affected Meta Box component is exposed to unauthenticated full takeover (CVSS 9.8). Update to the patched versions listed in the metadata: Meta Box AIO and Meta Box User Profile to 3.12.0, Meta Box Frontend Submission to 4.6.0.
- Sites that ran a vulnerable version should be audited for compromise: check for unexpected administrator accounts, and check for pages whose `post_content` was replaced with a `[mb_user_profile_register ...]` shortcode containing `role="administrator"` and/or `auto_login`.
- Updating removes the vulnerability but does not undo prior tampering, so injected content and rogue accounts must be cleaned up manually.

**Plugin & theme developers / agencies**
- The exploit needs both the frontend-submission and user-profile components active. Sites that use the standalone plugins should check each one separately.
- The advisory text and the metadata give different affected-version numbers for the AIO and User Profile plugins (the description says AIO up to 3.7.2 and standalone User Profile up to 2.5.14; the affected-software list says both <= 3.11.0). Treat anything below the patched versions as vulnerable.

**Hosting & platform**
- Consider WAF rules or log searches for requests carrying `rwmb_frontend_field_object_id` from unauthenticated clients, and for subsequent `wp_update_post` changes to page content.

## Technical details

The record describes a two-stage chain; no diff or patch was provided, so the details below come from the advisory text only.

1. **Object ID override.** `populate_via_query_string()` in the mb-frontend-submission component unconditionally replaces the form's target `object_id` with the value of the `rwmb_frontend_field_object_id` GET parameter. There is no authorization check on that value.
2. **Missing capability check on submit.** `render()` calls `user_can_edit()`, but `Form::process()` does not. An unauthenticated submission can therefore reach `wp_update_post()` against an arbitrary post or page ID and overwrite its `post_content` with an attacker-chosen shortcode.
3. **Shortcode attribute trust.** The mb-user-profile component processes the injected `[mb_user_profile_register]` shortcode and directly trusts its `role` and `auto_login` attributes with no role validation. Visiting the page registers a user with the attacker-chosen role (Administrator) and can log them in automatically.

The CWE is 269 (Improper Privilege Management). The advisory does not describe the exact fix; the patched releases (3.12.0 and 4.6.0) presumably add the missing authorization and/or role validation, but that is not confirmed by the record.
