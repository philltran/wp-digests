## Summary

Amelia (Premium) 8.0 through 9.6.2 has an unauthenticated privilege escalation. The customer update endpoint does not validate the attacker-controlled `type` parameter, so a caller can set their role to `manager`. When `externalId` is `0`, this triggers creation of a WordPress user with the `wpamelia-manager` role. The manager role can then be used to create a provider entity linked to an administrator user ID and overwrite that administrator's password. The issue is fixed in 9.6.3.

## Impact

**Site owners**
- Any site running Amelia Premium 8.0–9.6.2 is exposed to full administrator takeover by unauthenticated attackers (CVSS 9.8). Update to 9.6.3 or later.
- Sites that cannot update immediately should treat the plugin as a compromise risk, for example by disabling it or blocking access to its customer and booking endpoints at the WAF until patched.
- Review for indicators of prior exploitation: unexpected users with the `wpamelia-manager` role, unexpected Amelia provider entities linked to administrator accounts, and unexplained administrator password changes or resets.

**Plugin and theme developers / agencies**
- Audit client sites for the affected Premium version range. Only Amelia Premium is named in the advisory.
- If you have integrations that call Amelia's customer update endpoint, retest them against 9.6.3, since the `type` handling may have changed.

**Hosting and platform teams**
- This is a good candidate for fleet-wide version scanning and virtual patching. The advisory gives no detail on the specific route.

**Headless and REST consumers**
- No specific REST schema change is documented in the advisory.

## Technical details

The advisory describes a chain of three steps, all reachable without authentication:

1. **Role injection via `type`.** The customer update endpoint accepts an attacker-controlled `type` parameter without sufficient validation. This allows the caller to set the role to `manager` instead of a customer type.
2. **Manager user creation via `externalId = 0`.** When `externalId` is `0`, the plugin creates a new WordPress user with the `wpamelia-manager` role.
3. **Administrator takeover.** With manager privileges, the attacker creates a provider entity linked to an existing administrator's WordPress user ID. This lets them overwrite that administrator's password.

The weakness is classified as CWE-269 (Improper Privilege Management). The advisory does not name the specific route, controller, or class, and no diff is provided. The exact code change in 9.6.3 is therefore not known from the source material, but it presumably validates or restricts the `type` value accepted from unauthenticated callers.
