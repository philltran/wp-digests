# Membership Plugin – Kadence Memberships <= 4.0.0 - Unauthenticated Password Reset Link Poisoning to Account Takeover

## Summary

The Kadence Memberships plugin (≤4.0.0) contained a critical unauthenticated vulnerability allowing password reset link poisoning, which could lead to full account takeover. The legacy password reset handler accepted an attacker-controlled `rc_redirect` POST parameter and passed it directly to `wp_redirect()` and `add_query_arg()` without validation. When a victim clicked the poisoned reset link, the reset key was exfiltrated to the attacker, who could then replay it to hijack the account. This issue is patched in version 4.0.1.

## Impact

- **Site owners & administrators:** Must update to Kadence Memberships 4.0.1 immediately to prevent unauthenticated account takeover via poisoned password reset emails.
- **Plugin & theme developers:** No direct code changes required if you are not using the plugin's legacy password reset flow, but ensure your own custom reset handlers validate redirect parameters.
- **Hosting & platform teams:** Monitor for exploitation attempts targeting the `[login_form]` shortcode and `rc_process_lost_password_form()` endpoint; enforce updates across managed WordPress environments.
- **Action required:** Upgrade to 4.0.1 or later. No migration or configuration changes needed beyond the version bump.

## Technical details

The vulnerability resides in `legacy/includes/forms.php` within the `rc_process_lost_password_form()` function. The handler is triggered by a nonce exposed publicly via the `[login_form]` shortcode. Once triggered, the function reads `$_POST['rc_redirect']` and passes it unvalidated to two sinks:
- Line 243: `wp_redirect( esc_url( $_POST['rc_redirect'] ) . ... )`
- Line 306: `add_query_arg( array( 'key' => $key, 'login' => ... ), $_POST['rc_redirect'] )` inside `rc_send_password_reset_email()`
Because the redirect URL is attacker-controlled, an attacker can craft a password reset request where the reset link points to a malicious domain. When the victim clicks it, the reset key and login are transmitted to the attacker's server. The attacker then replays the captured key against the legitimate site's reset endpoint to complete the takeover. The fix in 4.0.1 validates and sanitizes the redirect parameter before it reaches these sinks.
