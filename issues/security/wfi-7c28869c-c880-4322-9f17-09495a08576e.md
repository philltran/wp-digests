# Forminator Forms <= 1.57.2 - Unauthenticated Arbitrary Shortcode Execution via 'current_url' Parameter

- **Affected:** Forminator Forms – Contact Form, Payment Form & Custom Form Builder (plugin) <= 1.57.2
- **Patched in:** 1.57.3

## Summary

Forminator Forms versions up to and including 1.57.2 pass a user-controlled value, reported as the `current_url` parameter, to `do_shortcode()` without adequate validation. An unauthenticated attacker can cause arbitrary registered shortcodes to be executed on the site. The issue is fixed in 1.57.3.

## Impact

**Site owners**
- Update Forminator Forms to 1.57.3 or later. Any site running <= 1.57.2 with the plugin active is exposed to unauthenticated attackers; no login is required.
- Severity is rated Critical (CVSS 9.1), so treat this as a priority patch.

**Plugin & theme developers / agencies**
- The real-world impact depends on which shortcodes are registered on the site. Any shortcode that reads data, performs actions, includes files, or renders privileged content can be triggered by an attacker. Audit your fleet for Forminator versions and for high-risk shortcodes registered by other plugins.
- If you cannot update immediately, consider deactivating the plugin or restricting access to the relevant request path (e.g. via a WAF rule) until patched. The advisory does not describe an official workaround.

**Hosting & platform teams**
- Prioritize scanning managed fleets for Forminator <= 1.57.2 and roll out the patched version.
- The advisory does not include indicators of compromise or exploitation status, so none can be stated here.

## Technical details

The advisory describes a code injection weakness (CWE-94): an action handled by the plugin takes a value, reported as the `current_url` parameter, and runs it through `do_shortcode()` without proper validation. Because the action is reachable by unauthenticated users, an attacker can supply shortcode markup (e.g. `[shortcode_tag attr="..."]`) in that parameter and have WordPress parse and execute it.
