# Blocksy Companion <= 2.1.46 - Unauthenticated Arbitrary File Upload via 'blc-review-images[]' Parameter

## Summary

Blocksy Companion plugin versions ≤ 2.1.46 contained an unauthenticated arbitrary file upload vulnerability in the `save_attachments` function. A custom `wp_check_filetype_and_ext` filter used substring matching to approve font files, allowing double-extension payloads like `shell.woff2.php` to bypass MIME validation and execute as PHP. Patched in 2.1.47, the fix enforces strict extension validation to prevent remote code execution via uploaded files.

## Impact

- **Site owners & administrators**: Update Blocksy Companion to 2.1.47 or later immediately to close an unauthenticated remote code execution vector.
- **Premium users**: The vulnerability only triggers when `blocksy-companion-pro` is active alongside the WooCommerce Extra (Advanced Reviews) and Custom Fonts extensions.
- **Free plugin users**: Not affected; the vulnerable code path is exclusive to the premium add-ons.
- **No code changes required** beyond updating the plugin to the patched version.

## Technical details

The vulnerability resided in the Custom Fonts extension, which hooked into `wp_check_filetype_and_ext` to approve files containing `.woff2` or `.ttf` as substrings via `strpos()`. This allowed double-extension filenames like `shell.woff2.php` to bypass MIME validation and be saved as executable PHP. The patch replaces the substring check with strict extension validation (using `PATHINFO_EXTENSION` or equivalent) within the `save_attachments` function, ensuring only legitimate font files are processed. The `blc-review-images[]` parameter remains the upload vector, but the filter now correctly rejects double extensions and enforces proper MIME/extension pairing.
