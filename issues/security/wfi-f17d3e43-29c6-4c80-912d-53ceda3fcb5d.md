# Automation Web Platform <= 4.8.6 - Unauthenticated Privilege Escalation via 'wawp_custom_fields' Parameter

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-09-24
- **CVE:** [CVE-2026-14281](https://www.cve.org/CVERecord?id=CVE-2026-14281)
- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-269: Improper Privilege Management
- **Affected:** Automation Web Platform – Notifications and OTP for WooCommerce, Advanced Country Code (plugin) <= 4.8.6
- **Patched in:** 4.8.7

- **Usefulness:** 5/5

## Summary

The Automation Web Platform (Notifications and OTP for WooCommerce) plugin exposes a public REST route, `POST /wp-json/wawp/v1/signup/<op>`, with no permission enforcement. Its `finish_registration_logic` function writes the caller-supplied `wawp_custom_fields` parameter straight into `update_user_meta()` with no key allowlist. An unauthenticated attacker can therefore register an account whose `wp_capabilities` and `wp_user_level` meta make it an administrator. Version 4.8.7 fixes it.

## Impact

**Site owners**
- Any site running version 4.8.6 or earlier is exposed to unauthenticated full site takeover (CVSS 9.8). Update to 4.8.7 or later immediately.
- Check for compromise: review administrator accounts and recently created users, especially accounts registered through the `wawp/v1/signup` route, and remove any unexpected admins. Also review plugins, themes and other changes made by unfamiliar admin accounts.
- Enabling OTP verification at signup does not mitigate the issue (see technical details).

**Plugin & theme developers / agencies**
- Audit client sites for this plugin, including multisite and staging copies.
- If you cannot update right away, deactivate the plugin or block `POST` requests to `/wp-json/wawp/v1/signup/` at the WAF or web server.

**Hosting & platform teams**
- Consider WAF rules that match requests to `wawp/v1/signup` containing `wawp_custom_fields` with `wp_capabilities` or `wp_user_level`.

**Headless & REST consumers**
- The route is reachable without authentication. If your signup flow depends on it, test it against 4.8.7 after updating.

## Technical details

The advisory describes three linked weaknesses (CWE-269). No diff or patched code was provided, so the exact fix is not described here.

1. **Missing permission enforcement.** The REST route `POST /wp-json/wawp/v1/signup/<op>` is publicly accessible and lacks effective permission enforcement.
2. **Mass assignment into user meta.** `finish_registration_logic` copies the attacker-controlled `wawp_custom_fields` parameter directly into `update_user_meta()` with no key allowlist. Sensitive keys such as `wp_capabilities` and `wp_user_level` can be set by the caller, which produces an administrator account.
3. **OTP bypass.** When OTP verification is enabled at signup, the `otp_transient` session token is returned in plaintext in the HTTP response body. `handle_magic_link_request()` marks that token as verified on any unauthenticated GET request containing it, without checking the OTP code value. No inbox or SMS access is needed.

Illustrative request shape (based on the advisory's description, not a verified exploit):

```http
POST /wp-json/wawp/v1/signup/<op>
...
wawp_custom_fields[wp_capabilities]=<administrator role data>
wawp_custom_fields[wp_user_level]=10
```

The generic remedy for this bug class is an explicit allowlist of writable meta keys plus a real `permission_callback`, but the advisory does not say how 4.8.7 implements the fix.
