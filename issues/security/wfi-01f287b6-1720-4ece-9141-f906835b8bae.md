# The WP Remote WordPress Plugin, Malcare Security, and BlogVault Backup & Staging < 6.65 - Unauthenticated Site Takeover via Brute Force

## Summary

The WP Remote, MalCare Security, and BlogVault Backup & Staging plugins, all versions before 6.65, generate the values used by their remote-connection feature with a weak pseudo-random number generator (CWE-338). An unauthenticated attacker can brute force those values and connect the site to their own remote management service, which gives them control of the site. Version 6.65 is the patched release for all three plugins.

## Impact

**Site owners**
- Any site running WP Remote, MalCare, or BlogVault Backup & Staging below 6.65 is exposed to unauthenticated takeover (CVSS 9.8). Update to 6.65 or later.
- The advisory describes the result as an attacker connecting the site to their own remote management software. After updating, check the plugin's connected-account/remote-connection state and confirm the site is linked only to your own account. The record does not describe indicators of compromise, so treat this as a precaution.

**Agencies and hosting/platform teams**
- These plugins are common on managed and client fleets. Inventory all three plugin slugs across your estate, not just one, because they share the affected range.
- Prioritize sites that are not yet connected to a remote account, or where the connection state is unclear. The advisory does not say which states are exploitable, so do not assume connected sites are safe.

**Plugin and theme developers**
- No API or hook changes are documented. The general lesson: use `wp_generate_password()`, `random_bytes()`, or `random_int()` rather than `rand()`, `mt_rand()`, or `uniqid()` for any token that gates a trust relationship.

## Technical details

The Wordfence record gives only a high-level description. The root cause is CWE-338: a weak PRNG produces the secret or token used by the plugins' remote connection feature. This makes the value predictable or brute-forceable by an unauthenticated attacker, who can then complete the connection handshake and register the site with attacker-controlled remote management software.

The record does not name the vulnerable function, file, endpoint, or the exact generator used, and no diff or patch is provided. The fix is described only as "update to 6.65". Details about how 6.65 changes token generation are not available from this source.
