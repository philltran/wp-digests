# ProSolution WP Client <= 2.0.8 - Unauthenticated Arbitrary File Deletion via 'newfilename' and 'filename' Parameters

## Summary

ProSolution WP Client is vulnerable to unauthenticated arbitrary file deletion caused by insufficient path validation in `proSol_fileDeleteProcess`. An attacker can first call `proSol_fileUploadModalProcess` to poison their session with a path-traversal key, then call `proSol_fileDeleteProcess` using that key as the `filename` parameter. Both steps require only the publicly exposed frontend nonce. Deleting files such as `wp-config.php` can lead to remote code execution.

## Impact

- **Site owners:** If the plugin is installed, update to the patched release immediately; unauthenticated attackers can delete arbitrary server files, potentially enabling remote code execution.
- **Hosting and platform teams:** Apply the patched release and review file integrity for signs of unexpected deletion.
- **Plugin and theme developers:** No direct code change is required unless the plugin is used in a product; ensure the installed plugin is updated.
- **Headless and REST consumers:** No action required if the plugin is not installed.

## Technical details

The vulnerable code path is `proSol_fileDeleteProcess`, which does not sufficiently validate the file path supplied through the `newfilename` and `filename` parameters. The advisory describes a two-step unauthenticated flow: an attacker calls `proSol_fileUploadModalProcess` to store a path-traversal key in their own session, then calls `proSol_fileDeleteProcess` with that key as the `filename` value. The only prerequisite is the publicly exposed frontend nonce.
