# Advanced Product Fields Extended for WooCommerce <= 3.1.6 - Unauthenticated Arbitrary File Deletion

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-09-09
- **CVE:** [CVE-2026-81789](https://www.cve.org/CVERecord?id=CVE-2026-81789)
- **CVSS:** 9.1 (Critical)
- **CWE:** CWE-22: Improper Limitation of a Pathname to a Restricted Directory ('Path Traversal')
- **Affected:** Advanced Product Fields Extended for WooCommerce (plugin) <= 3.1.6
- **Patched in:** 3.1.7
- **Researchers:** Maarten
- **Link:** [https://www.wordfence.com/threat-intel/vulnerabilities/id/d430c863-6af1-4519-b276-3bf7e2b2d3c2](https://www.wordfence.com/threat-intel/vulnerabilities/id/d430c863-6af1-4519-b276-3bf7e2b2d3c2)
- **Usefulness:** 5/5

## Summary

Advanced Product Fields Extended for WooCommerce versions up to and including 3.1.6 fail to validate file paths before deleting files, so an unauthenticated attacker can delete arbitrary files on the server. Deleting a file such as `wp-config.php` can lead to remote code execution. The issue is fixed in 3.1.7.

## Impact

- **Site owners:**
  - Update to 3.1.7 or later immediately. The flaw is exploitable without authentication and is rated critical.
  - If you cannot update, deactivate and remove the plugin until you can.
  - Sites running <= 3.1.6 that are internet-facing should be checked for unexpected missing files (especially `wp-config.php`, `.htaccess`, and index/security files) and for signs of a reinstall or takeover.
- **Plugin & theme developers / agencies:** Audit client WooCommerce sites for this plugin and its installed version. No API changes are documented; the fix is a plain version bump.
- **Hosting & platform teams:** Consider blocking or monitoring unauthenticated requests to this plugin's deletion endpoints until patched. The advisory does not name the specific endpoint, so signatures should be based on your own review of the plugin.
- **Headless & REST consumers:** The advisory does not say whether the vulnerable path is reached via REST, admin-ajax, or another entry point, so do not assume a headless setup is unaffected.

## Technical details

The advisory classifies this as CWE-22 (path traversal): the plugin does not sufficiently validate a file path before it is used in a deletion operation. Because the entry point is reachable by unauthenticated users, an attacker can supply a path pointing outside the intended directory and have the server delete it.

The record does not identify the vulnerable function, hook, or file, nor does it describe the exact patch. Typical hardening for this class of bug would be capability/nonce checks plus canonicalizing the path and confirming it resolves inside the expected uploads directory, but that is not confirmed by the source, so verify against the 3.1.7 diff if you need specifics.

The highest-impact outcome cited is deleting `wp-config.php`, which can push WordPress into the installer flow and let an attacker point the site at a database they control.
