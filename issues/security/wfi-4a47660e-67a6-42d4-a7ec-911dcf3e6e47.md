## Summary

The WPLP Cookie Consent plugin (<= 4.4.1) lacks file type validation on an upload handler that unauthenticated users can reach. An attacker can place arbitrary files on the server, which may lead to remote code execution. Version 4.4.2 fixes the issue.

## Impact

**Site owners**
- Update to 4.4.2 or later immediately. The flaw is unauthenticated and rated CVSS 9.8, so any site running <= 4.4.1 is exposed to remote exploitation without an account.
- If the plugin was active on an unpatched version, check for unexpected files (especially `.php` or other executable types) in `wp-content/uploads/` and the plugin's directories, and review access logs for anomalous POST requests to the plugin's endpoints.
- If patching is not possible right away, deactivate and remove the plugin until it can be updated.

**Plugin & theme developers / agencies**
- Audit client sites and managed fleets for this plugin and its version. Sites where it is bundled or mandated by a compliance workflow are easy to overlook.

**Hosting & platform teams**
- Consider WAF or virtual-patching rules for unauthenticated upload requests targeting this plugin. The advisory does not name the vulnerable endpoint, so specific rules cannot be derived from it.

**Breaking changes / deprecations:** none reported.
