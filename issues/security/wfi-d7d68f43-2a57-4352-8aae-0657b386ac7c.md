## Summary

WP-BusinessDirectory versions up to 4.0.1 contain an unauthenticated arbitrary file deletion vulnerability. The flaw stems from insufficient path validation in the `remove()` method of the `JBusinessDirectoryControllerUpload` class, allowing attackers to supply path traversal sequences via the `_filename` parameter. The vendor patch restricts path resolution to prevent deletion of files outside the intended directory.

## Impact

- **Site owners & administrators**: Update to the patched release immediately to prevent unauthenticated attackers from deleting arbitrary server files.
- **Plugin & theme developers**: No direct code changes required; rely on the vendor patch.
- **Hosting & platform teams**: Monitor for `unlink()` abuse or unexpected file deletions on affected sites; consider WAF rules blocking `task=upload.remove` with `../` payloads until patched.
- **Headless & REST consumers**: No impact; the vulnerability is isolated to the plugin's frontend routing endpoint.

## Technical details

The vulnerability exists in the `JBusinessDirectoryControllerUpload::remove()` method, exposed via the unauthenticated `task=upload.remove` frontend routing endpoint. The `_filename` parameter is processed with a RAW filter, bypassing sanitization. The helper function `makePathFile()` only normalizes directory separators and fails to strip `../` sequences. When `_path_type=2` is passed, the base directory resolves to the plugin's site folder, but the unsanitized traversal allows `unlink()` to target arbitrary paths accessible to the web server process. Patched versions add strict path validation to ensure resolved paths remain within the intended directory boundary before calling `unlink()`.
