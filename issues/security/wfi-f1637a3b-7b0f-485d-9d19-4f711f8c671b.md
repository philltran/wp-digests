# Frontend Admin by DynamiApps <= 3.29.12 - Unauthenticated Account Takeover via '_acf_objects' Object Identifier

- **Usefulness:** 5/5

## Summary

Frontend Admin by DynamiApps contains an unauthenticated authentication-bypass flaw that leads to full account takeover. The `pre_update_value` function performs no capability or ownership check, and `ActionPost::conditions_logic()` skips its `current_user_can('edit_post')` gate whenever the submitted post ID is non-numeric (for example `user_1`). An anonymous form submission can therefore be routed at an arbitrary user record and overwrite that user's email address, after which the native WordPress password-reset flow hands over the account, including administrators. The issue is fixed in 3.29.13.

## Impact

- **Site owners:** Any site running Frontend Admin <= 3.29.12 is exposed to unauthenticated administrator takeover. Update to 3.29.13 or later immediately. If you cannot update right away, deactivate the plugin.
- **Post-incident review:** On sites that were exposed, audit for unexpected changes to user email addresses (especially administrators), unsolicited password-reset emails or requests, and newly created or modified admin accounts.
- **Plugin & theme developers:** Code that integrates with Frontend Admin forms or builds on ACF-style object identifiers (`_acf_objects`) should not assume that a non-numeric object ID such as `user_1` is authorized by the same checks as a numeric post ID.
- **Hosting & platform teams:** The CVSS is 9.8 and no authentication is needed, so this is a candidate for virtual patching or WAF rules and for fleet-wide version checks.
- **Headless & REST consumers:** The advisory describes exploitation through unauthenticated form submissions; it does not mention REST routes.

## Technical details

Per the advisory, two defects combine:

1. **Missing authorization in `pre_update_value`.** The function writes submitted field values to the target object without any capability or ownership check.
2. **Authorization short-circuit in `ActionPost::conditions_logic()`.** The `current_user_can('edit_post')` gate is bypassed when the post ID is non-numeric. A value like `user_1` (the ACF-style `user_{ID}` object identifier, supplied via the `_acf_objects` parameter) is non-numeric, so the check is skipped and the submission is routed to a user record rather than a post.

An unauthenticated attacker can therefore overwrite the registered email address of any user, then trigger the standard password-reset flow (`wp-login.php?action=lostpassword`) to receive a reset link for that account. The weakness is classified as CWE-287 (Improper Authentication).

No patch diff is included in the source record, so the exact code change in 3.29.13 is not described here. Upgrading to 3.29.13 or newer is the vendor-supported remediation.
