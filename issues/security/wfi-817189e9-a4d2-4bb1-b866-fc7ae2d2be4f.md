## Summary

The YAHMAN Add-ons plugin for WordPress has a critical unauthenticated remote code execution vulnerability in all versions up to and including 0.9.30. User-supplied input is executed on the server without sufficient validation, so an attacker needs no account to run arbitrary code. The issue is fixed in 0.9.31.

## Impact

**Site owners**
- Any site running YAHMAN Add-ons <= 0.9.30 is exposed to full server-side code execution by unauthenticated attackers. Update to 0.9.31 or later immediately.
- If the plugin was active on a publicly reachable site while vulnerable, treat the site as potentially compromised: review for unexpected files, admin users, scheduled events, and modified core/plugin/theme files, and rotate credentials and salts as appropriate.
- If you cannot update immediately, deactivate and remove the plugin.

**Agencies / hosting & platform teams**
- Audit managed fleets for the plugin slug and version (for example via `wp plugin list`) and prioritize patching.
- Consider WAF rules or virtual patching where available until updates are applied.

**Plugin & theme developers**
- No API, hook, or deprecation changes are documented. The record describes a patch only.

## Technical details

The advisory classifies the flaw as CWE-94 (Code Injection): input supplied by the user reaches a code-execution sink without adequate validation. It is reachable without authentication, which drives the CVSS 9.8 rating.
