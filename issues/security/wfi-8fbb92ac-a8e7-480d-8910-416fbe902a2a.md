# Divi Ajax Filter <= 5.1.2 - Unauthenticated Local File Inclusion via 'custom_loop_template' Parameter

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-09-03
- **CVE:** [CVE-2026-11613](https://www.cve.org/CVERecord?id=CVE-2026-11613)
- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-98: Improper Control of Filename for Include/Require Statement in PHP Program ('PHP Remote File Inclusion')
- **Affected:** Divi Ajax Filter (plugin) <= 5.1.2
- **Patched in:** 5.1.3
- **Researchers:** h0xilo
- **Link:** [https://www.wordfence.com/threat-intel/vulnerabilities/id/8fbb92ac-a8e7-480d-8910-416fbe902a2a](https://www.wordfence.com/threat-intel/vulnerabilities/id/8fbb92ac-a8e7-480d-8910-416fbe902a2a)
- **Usefulness:** 5/5

## Summary

Divi Ajax Filter versions up to and including 5.1.2 contain an unauthenticated Local File Inclusion flaw via the `custom_loop_template` parameter. An attacker can cause the plugin to include and execute arbitrary `.php` files on the server. It is only exploitable when the `loop_templates` parameter is set to `custom-template`. The issue is fixed in 5.1.3.

## Impact

**Site owners**
- Update Divi Ajax Filter to 5.1.3 or later as soon as possible. The CVSS score is 9.8 (Critical) and no authentication is required.
- Exploitation can bypass access controls, expose sensitive data, or lead to code execution, particularly where `.php` files can be uploaded and then included (e.g. via a separate upload vector).

**Plugin & theme developers / agencies**
- Audit client sites for the plugin and its version, including Divi child-theme setups and mu-plugin bundles that may ship a copy.
- If you cannot update immediately, consider blocking or filtering requests to the plugin's AJAX endpoint that carry `custom_loop_template` or `loop_templates=custom-template` at the WAF level. This is a stopgap, not a fix.
- If you use custom loop templates through the plugin, re-test them after updating, since the fix may change how the template path is resolved (the source record does not describe the patch).

**Hosting & platform teams**
- Consider checking access logs for requests containing `custom_loop_template` with path traversal sequences or unexpected `.php` paths, and for unexpected PHP files in writable directories.

**Headless & REST consumers**
- No specific impact is documented beyond the affected request path.

## Technical details

The vulnerability is classed as CWE-98 (improper control of filename for include/require in PHP). The user-supplied `custom_loop_template` parameter is used to build the path of a file that the plugin includes, without adequate restriction, so an unauthenticated request can cause an arbitrary `.php` file on the server to be included and executed.

The code path is reachable only when the `loop_templates` parameter is set to `custom-template`.

The source record does not include the diff or describe the specific patch in 5.1.3, so the exact validation added (allowlist, path normalization, capability check, etc.) is not stated here. Review the 5.1.3 changelog or code diff if you need specifics.
