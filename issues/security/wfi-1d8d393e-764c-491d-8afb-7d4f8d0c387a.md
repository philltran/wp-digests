# Single Sign On For TNG <= 2.0.0 - Unauthenticated Privilege Escalation via Unverified Password Change

## Summary

The Single Sign On For TNG plugin (≤ 2.0.0) contained a critical unauthenticated privilege escalation vulnerability that allowed attackers to reset any user’s password, including administrators, without verification. The flaw stemmed from the `ssoprocess_ajax()` AJAX handler accepting a `setnewpassword` operation and calling WordPress’s `reset_password()` function without validating account ownership or requiring a secure token. Patched in version 2.1.0, this change closes an unverified password reset path that could lead to complete site takeover.

## Impact

- **Plugin users (≤ 2.0.0):** Immediate action required. Update to 2.1.0 or later to prevent unauthenticated password resets.
- **Site owners/admins:** If running an affected version, audit accounts for unauthorized changes, as the flaw allowed complete site takeover.
- **Hosting & platform teams:** Monitor server logs for requests to `wp_ajax_nopriv_ssoprocess_ajax` and enforce plugin update policies.
- **Plugin & theme developers:** No direct API changes or deprecations; this is a third-party security patch.

## Technical details

The vulnerability resided in the `ssoprocess_ajax()` function, registered on `wp_ajax_nopriv_ssoprocess_ajax`, which accepted an unauthenticated `email` parameter and a `setnewpassword` operation. Instead of validating account ownership or requiring a secure token, the handler passed the resolved user directly to `reset_password()`. The only guard was `check_ajax_referer()` using `ssoajaxnonce`, but this nonce was exposed to the frontend via `wp_localize_script()` into the `SSOPWDREQUIREMENT` JavaScript object. Because WordPress computes logged-out nonces against a shared anonymous session, attackers could scrape a valid nonce from any page and reuse it to authenticate the request. The 2.1.0 patch resolves this by enforcing proper ownership verification and capability checks before invoking `reset_password()`.
