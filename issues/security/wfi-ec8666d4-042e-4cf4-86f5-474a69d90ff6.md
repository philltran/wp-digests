## Summary

The Post Grid and Gutenberg Blocks (ComboBlocks) plugin exposes several functions in `includes/blocks/form-wrap/function.php` that let unauthenticated visitors trigger arbitrary WordPress action hooks. The flaw affects versions 2.2.85 through 2.3.22 and is fixed in 2.3.23. The advisory rates it Critical.

## Impact

**Site owners**
- Update Post Grid / ComboBlocks to 2.3.23 or later if you run any version from 2.2.85 to 2.3.22.
- Exploitation needs no authentication. The advisory says attackers can execute actions with hooks "granted no other security controls are present in the function." What an attacker can actually do depends on which actions are registered on the site (core, other plugins, theme).

**Plugin & theme developers / agencies**
- Audit client sites for the affected version range, including sites where the plugin is a dependency of a theme or starter kit.
- Because the exposure is arbitrary hook invocation, the blast radius varies per site. Any action callback that assumes it is only reached in a trusted context is a potential escalation path.

**Hosting & platform teams**
- Consider fleet-wide scanning for the plugin slug and affected versions. No mitigation beyond patching is described in the advisory.

## Technical details

The advisory places the vulnerable code in several functions in `~/includes/blocks/form-wrap/function.php` (the form-wrap block). The flaw is classified as unauthenticated hook injection (CWE-94). Per the description, attacker-controlled input can cause the plugin to fire WordPress action hooks, apparently without an authorization or allow-list check in those functions.

The advisory does not name the specific functions, request parameters, or hook-dispatch mechanism (e.g. `do_action()` with a user-supplied tag), and no patch diff is provided. The exact fix in 2.3.23 cannot be described from the source material. Review the 2.3.22 to 2.3.23 changeset for that file to confirm the nature of the fix.
