# JetFormBuilder <= 3.6.2 - Unauthenticated Privilege Escalation via '_jet_engine_booking_form_id' Parameter

- **CWE:** CWE-269: Improper Privilege Management
- **Affected:** JetFormBuilder — Dynamic Blocks Form Builder (plugin) <= 3.6.2
- **Patched in:** 3.6.2.1

- **Usefulness:** 5/5

## Summary

JetFormBuilder up to and including 3.6.2 does not check that the form ID submitted in the `_jet_engine_booking_form_id` parameter belongs to a JetFormBuilder form. The plugin parses the content of whatever post the ID references as form schema and runs an Advanced Validation server-side callback. An unauthenticated attacker can exploit this to create a new administrator-level user. The issue is fixed in 3.6.2.1.

## Impact

**Site owners**
- Any site running JetFormBuilder <= 3.6.2 is exposed to unauthenticated takeover (CVSS 9.8). Update to 3.6.2.1 or later immediately.
- Review **Users → All Users** for administrator accounts you do not recognize, and check for unexpected recent registrations. Rotate credentials if any unknown admin exists.

**Plugin & theme developers / agencies**
- Audit your fleet for JetFormBuilder versions and prioritize patching, since the attack needs no authentication.
- If you have custom code relying on Advanced Validation callbacks, retest after the update.

**Hosting & platform teams**
- Consider virtual patching or WAF rules for form submissions carrying `_jet_engine_booking_form_id` until sites are updated.

**Headless & REST consumers**
- No specific REST API change is described in the advisory.

## Technical details

The advisory's root cause is missing validation on the submitted form ID. The request parameter `_jet_engine_booking_form_id` is accepted as-is, and the referenced post is treated as a form without verifying it is a JetFormBuilder form. Its content is then parsed as form schema, and an Advanced Validation server-side callback is executed from that schema. Because the post is not restricted to the plugin's form post type, an attacker can point the parameter at another post whose content they influence, which leads to administrator account creation (CWE-269).

The advisory does not include a diff, the exact functions involved, or the precise callback mechanism, so those details are not confirmed here. The fix in 3.6.2.1 is described only as a patched release; the advisory implies, but does not state, that the fix validates the form ID before parsing.
