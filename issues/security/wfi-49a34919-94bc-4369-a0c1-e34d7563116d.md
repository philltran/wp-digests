# User Registration PRO – Custom Registration Form, Login Form, and User Profile WordPress Plugin <= 5.4.5 - Unauthenticated Privilege Escalation via Account Takeover

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability

- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-287: Improper Authentication
- **Affected:** User Registration PRO – Custom Registration Form, Login Form, and User Profile WordPress Plugin (plugin) <= 5.4.5
- **Patched in:** 5.4.6
- **Researchers:** 0xd4rk5id3

- **Usefulness:** 5/5

## Summary

User Registration PRO (<= 5.4.5) does not properly verify a user's identity before updating account details. An unauthenticated attacker can modify details of arbitrary users, including administrators, and use that to take over the account and escalate privileges. Version 5.4.6 fixes it.

## Impact

**Site owners**
- Any site running User Registration PRO <= 5.4.5 is exposed to unauthenticated account takeover of any user, including administrators (CVSS 9.8).
- Update to 5.4.6 or later immediately.
- If the site was exposed, audit administrator and other privileged accounts for unexpected changes to email addresses, passwords, or roles, and review recent password-reset activity. The advisory does not describe indicators of compromise, so treat this as general hygiene rather than a known signature.

**Plugin & theme developers / agencies**
- Inventory client sites for this plugin and prioritize patching.
- No public API changes are described in the advisory.

**Hosting & platform teams**
- Consider prioritizing this in managed-update or virtual-patching queues, given the unauthenticated, critical nature of the flaw.

## Technical details

The advisory classifies the flaw as CWE-287 (Improper Authentication): the plugin does not validate the requesting user's identity before updating user details. Because of that, an unauthenticated request can alter details of an arbitrary account, and the attacker can then use the changed details to gain access to that account (account takeover).

The advisory does not name the vulnerable function, endpoint, AJAX action, or the specific fields that can be changed, and no diff or patch is included in the record. Those specifics are therefore not stated here.
