# WP Recipe Maker <= 10.8.1 - Unauthenticated Arbitrary Shortcode Execution via Recipe Comment Content

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-09-18
- **CVE:** [CVE-2026-89274](https://www.cve.org/CVERecord?id=CVE-2026-89274)
- **CVSS:** 9.1 (Critical)
- **CWE:** CWE-94: Improper Control of Generation of Code ('Code Injection')
- **Affected:** WP Recipe Maker (plugin) <= 10.8.1
- **Patched in:** 10.8.2
- **Researchers:** Md. Moniruzzaman Prodhan (NomanProdhan)

- **Usefulness:** 5/5

## Summary

WP Recipe Maker <= 10.8.1 runs `do_shortcode()` recursively over every scalar in the recipe's structured metadata array in `WPRM_Metadata::sanitize_metadata()`. That array includes `reviewBody`, which is filled verbatim from the `comment_content` of approved `wprm-comment-rating` comments. A commenter can therefore put shortcode tokens in a rated comment and have them executed server-side on every render of the recipe page. The output lands in the page's JSON-LD `reviewBody` and is visible to all visitors. Version 10.8.2 fixes it.

## Impact

**Site owners**
- Any site running WP Recipe Maker <= 10.8.1 with recipe comment ratings enabled is exposed. Update to 10.8.2.
- Exploitation requires the attacker's rated comment to be approved, either automatically under your comment settings or by a moderator. Sites that auto-approve comments (or previously approved commenters) are the most exposed.
- Existing approved `wprm-comment-rating` comments containing shortcode tokens keep executing on page loads until the plugin is updated. Review them for unexpected `[...]` tokens.
- Output from any registered shortcode (attachment captions, private post fields, or other data exposed by installed shortcodes) can leak into the JSON-LD `reviewBody` on public recipe pages.

**Plugin & theme developers / agencies**
- The blast radius depends on which shortcodes are registered on the site. Any shortcode that returns sensitive data or has side effects is reachable without authentication.
- No API changes are documented for consumers of the plugin.

**Hosting & platform teams**
- Consider WAF or monitoring for shortcode-like content in comment submissions until sites are patched. This is a mitigation only, not a substitute for updating.

## Technical details

The advisory places the flaw in `WPRM_Metadata::sanitize_metadata()`, which recursively calls `do_shortcode()` on every scalar field of the recipe's structured metadata array (the JSON-LD data). One of those fields, `reviewBody`, is populated verbatim from `comment_content` of approved `wprm-comment-rating` comments. Shortcode tokens are not stripped or escaped before execution.

The existing `wp_strip_all_tags()` and `strip_shortcodes()` calls run only on the resulting output string, after execution has already happened, so they do not prevent server-side shortcode invocation.

The result is that arbitrary registered shortcodes execute on every recipe page render, and their output is embedded in the page's JSON-LD `reviewBody`. The attack is unauthenticated, but the comment must pass the site's approval threshold first.

The upstream record does not include the diff or describe the exact fix in 10.8.2, so the precise change is not stated here.
