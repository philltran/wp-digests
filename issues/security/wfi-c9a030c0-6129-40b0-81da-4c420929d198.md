# Appointment Booking Plugin <= 5.7.0 - Unauthenticated Arbitrary Shortcode Execution via First/Last Name Field

- **Type:** Vulnerability

- **Affected:** Appointment Booking Plugin – LatePoint | Calendar & Scheduling for WordPress (plugin) <= 5.7.0

- **Usefulness:** 5/5

## Summary

LatePoint (Appointment Booking Plugin) versions up to and including 5.7.0 allow unauthenticated attackers to plant a shortcode payload in the first/last name field during the booking flow. When the Customer Cabinet block, rendered by `render_customer_dashboard()`, outputs the stored name into the content stream, WordPress core's `do_shortcode` filter (priority 11) re-parses it and executes it. The result is arbitrary shortcode execution. The issue is fixed in 5.7.1.

## Impact

**Site owners**
- Any site running LatePoint <= 5.7.0 with the Customer Cabinet block in use is exposed to unauthenticated exploitation. Update to 5.7.1 or later.
- Review existing customer records for names containing shortcode syntax (`[` ... `]`), since a payload planted before patching stays stored and could still be output by the block if the plugin is not updated.

**Plugin & theme developers**
- Severity depends on which shortcodes are registered on the site. Any shortcode with side effects or that exposes data, from any plugin or theme, becomes reachable by an unauthenticated attacker.
- Custom code or templates that print LatePoint customer names into post content or other filtered content streams should escape or strip shortcode brackets on output.

**Hosting & platform**
- Consider prioritizing this for fleet-wide patching given the unauthenticated vector and critical CVSS. The source does not describe any WAF mitigation.

## Technical details

The source record describes a two-stage flaw. It does not include a diff, so the exact code fix is not stated.

1. **Plant:** the unauthenticated booking flow accepts a first/last name value without validating or neutralizing shortcode syntax, and stores it.
2. **Trigger:** `render_customer_dashboard()` (the Customer Cabinet block renderer) outputs the stored name into the content stream. Core's `do_shortcode` filter, hooked on `the_content` at priority 11, then parses and executes any shortcode in that output.

The root cause is classed as CWE-94 (code injection): a stored value reaches `do_shortcode` without proper validation. Version 5.7.1 is the patched release, and the record does not say whether the fix validates on input, escapes on output, or both.

A general hardening pattern for output that flows through `the_content` is to neutralize brackets in user-supplied strings:

```php
$safe_name = str_replace( array( '[', ']' ), array( '&#91;', '&#93;' ), $name );
```
