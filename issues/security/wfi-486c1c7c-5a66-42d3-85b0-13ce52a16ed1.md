# Visual Composer Website Builder <= 45.16.0 - Unauthenticated Local File Inclusion via 'vcv-template' Parameter

- **Type:** Vulnerability

- **Affected:** Visual Composer Website Builder (plugin) <= 45.16.0
- **Patched in:** 45.16.1

- **Usefulness:** 5/5

## Summary

The Visual Composer Website Builder plugin contains an unauthenticated Local File Inclusion vulnerability in versions up to and including 45.16.0. The `vcv-template` parameter is used to select a file that the server includes and executes, and it is not adequately restricted. An unauthenticated attacker can make the plugin include arbitrary local files and run any PHP they contain. Version 45.16.1 fixes it.

## Impact

**Site owners**
- Update Visual Composer Website Builder to 45.16.1 or later as soon as possible. The issue is rated CVSS 9.8 (Critical) and requires no authentication.
- Sites running 45.16.0 or earlier are exposed. Consequences named in the advisory: bypassing access controls, disclosing sensitive data, and code execution where images or other "safe" file types can be uploaded and then included.
- If you cannot update immediately, deactivating the plugin is the only mitigation supported by the source material. The advisory does not describe a workaround.
- Consider reviewing access logs for requests containing the `vcv-template` parameter, particularly with path-like values, and checking for unexpected files in upload directories.

**Plugin & theme developers / agencies**
- Audit client sites and any bundled or dependent installs for the affected plugin version.
- No API, hook, or configuration changes are documented; the fix is delivered as a plugin update.

**Hosting & platform teams**
- This is a good candidate for fleet-wide version scanning and, where available, WAF rules targeting `vcv-template`.

## Technical details

The advisory classifies this as CWE-98 (improper control of filename for include/require in PHP). The vulnerable input is the `vcv-template` request parameter, which reaches an include/require in the plugin without sufficient validation, so an attacker can point it at arbitrary files on the local filesystem. Any PHP within the included file is executed.

The exploitation chain to full code execution depends on the attacker being able to place a file on the server, such as an uploaded image containing PHP. Plain inclusion of existing files can still expose sensitive data or bypass access controls.

The source material does not include the diff, the specific file or function containing the include, or a description of how 45.16.1 changes the handling of the parameter, so those details are not covered here.
