# ShopBuilder Pro – Elementor WooCommerce Builder Addons <= 2.2.0 - Unauthenticated Arbitrary File Deletion

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-08-24
- **CVE:** [CVE-2026-32477](https://www.cve.org/CVERecord?id=CVE-2026-32477)
- **CVSS:** 9.1 (Critical)
- **CWE:** CWE-22: Improper Limitation of a Pathname to a Restricted Directory ('Path Traversal')
- **Affected:** Shopbuilder Pro (plugin) <= 2.2.0
- **Researchers:** Jamaal ahmed
- **Link:** [https://www.wordfence.com/threat-intel/vulnerabilities/id/2c1b53b9-e70b-4204-a00e-8745611606bf](https://www.wordfence.com/threat-intel/vulnerabilities/id/2c1b53b9-e70b-4204-a00e-8745611606bf)
- **Usefulness:** 5/5

## Summary

ShopBuilder Pro (Elementor WooCommerce Builder Addons) through 2.2.0 fails to properly validate file paths in a code path reachable without authentication. An unauthenticated attacker can delete arbitrary files on the server. Deleting a file such as `wp-config.php` can lead to remote code execution, which is why the issue is rated critical. No patched version is available.

## Impact

**Site owners**
- Any site running ShopBuilder Pro <= 2.2.0 is exposed to unauthenticated arbitrary file deletion. No login or user interaction is required.
- Wordfence states there is no known patch. Its guidance is to assess risk and consider uninstalling the plugin and replacing it.
- Deleting `wp-config.php` can put the site into a state that enables takeover, per the advisory (remote code execution).

**Agencies / platform and hosting teams**
- Inventory client sites for this plugin and its version. Since no fix exists, deactivating and removing it is the only complete mitigation available from the record.
- Compensating controls such as a WAF rule or restrictive filesystem permissions (a non-writable web root outside `wp-content/uploads`) may reduce blast radius, but the record does not describe the vulnerable endpoint, so any WAF rule cannot be targeted from this information.
- Confirm you have current backups of site files and the database, since the attack destroys files.

**Plugin/theme developers**
- No API, hook, or behavior change to adapt to. This is a plugin-specific vulnerability.

## Technical details

The record gives limited detail. It classifies the flaw as CWE-22 (path traversal): insufficient validation of a file path in versions up to and including 2.2.0, which lets an unauthenticated request cause deletion of files chosen by the attacker. CVSS is 9.1 (Critical).

The advisory does not name the vulnerable function, AJAX action, REST route, or parameter, and no diff or patched version is available, so the exact entry point cannot be stated from the source material. The advisory says only that the outcome can be remote code execution when a critical file like `wp-config.php` is deleted.
