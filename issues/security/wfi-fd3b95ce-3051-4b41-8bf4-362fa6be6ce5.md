## Summary

The Broken Link Checker plugin contains an unauthenticated remote code execution vulnerability caused by insufficient validation of user-supplied input before it is executed (CWE-94, code injection). An unauthenticated attacker can run arbitrary code on the server. The issue is fixed in 2.4.12.

## Impact

**Site owners**
- Any site running Broken Link Checker below 2.4.12 is exposed to unauthenticated RCE, i.e. full site and likely server-level compromise. CVSS is 9.8 (Critical).
- Update to 2.4.12 or later immediately. If you cannot update right away, deactivate and remove the plugin until you can.
- If a site ran a vulnerable version while publicly reachable, consider reviewing it for signs of compromise (unexpected PHP files, new admin users, modified core/plugin files).

**Plugin & theme developers / agencies**
- Audit managed sites and any bundled or mu-plugin deployments for the affected version range, including sites pinned via Composer or a lockfile.

**Hosting & platform teams**
- Consider scanning fleets for the plugin slug and version, and applying WAF rules if your provider offers them.

No API, hook, or configuration changes are documented. The only required action is updating the plugin.

The advisory gives no code-level detail: no vulnerable function, file, endpoint, or hook is named. It states only that user-supplied input is insufficiently validated before being executed, which maps to CWE-94 and allows unauthenticated arbitrary code execution.
