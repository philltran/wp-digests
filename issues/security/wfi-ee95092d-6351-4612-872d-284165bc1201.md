# SAML Single Sign On <= 5.4.3 - Unauthenticated Authentication Bypass via 'SAMLResponse' Parameter Signature Algorithm Confusion

## Summary

The SAML Single Sign On – SSO Login plugin for WordPress has been patched to prevent an unauthenticated authentication bypass. Versions 5.4.3 and earlier incorrectly allowed the `SignatureMethod` algorithm attribute from the incoming `SAMLResponse` to dictate how the IdP’s public key was processed, enabling attackers to force an HMAC-SHA1 validation path and forge valid assertions. Updating to 5.4.4 enforces the locally configured signature algorithm, closing the cryptographic signature confusion vector.

## Impact

- **Plugin users & site owners**: Must update to version 5.4.4 or later to prevent unauthenticated account takeover. No code changes or configuration migrations are required; a standard plugin update resolves the issue.
- **Headless & SSO integrations**: SAML-based authentication flows will resume normal cryptographic validation once patched. No additional setup or migration steps are needed.

## Technical details

The vulnerability resided in `Mo_SAML_Utilities::mo_saml_cast_key()`, which previously extracted the `SignatureMethod` algorithm directly from the attacker-controlled `SAMLResponse` parameter. By trusting this external attribute, an attacker could supply a forged assertion that caused the plugin to recast the IdP’s RSA public key as an HMAC-SHA1 shared secret, bypassing signature verification. The 5.4.4 patch replaces this dynamic extraction with a strict enforcement of the locally configured signature algorithm, ensuring the key is always processed according to the plugin’s settings rather than the incoming SAML payload.
