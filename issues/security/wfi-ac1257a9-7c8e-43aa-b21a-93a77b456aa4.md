## Summary

The MIPL Checkout Fields Manager for WooCommerce plugin (grouped checkout fields) lets unauthenticated visitors upload arbitrary files to the server. The `mipl_wc_upload_file` function performs no file type validation, so an attacker can place executable files such as PHP scripts in the web-accessible filesystem, which can lead to remote code execution. Version 1.2.3 fixes it.

## Impact

**Site owners**
- Any WooCommerce site running MIPL Checkout Fields Manager <= 1.2.2 is exposed to unauthenticated exploitation; no account or purchase is required.
- Update to **1.2.3** or later immediately. If you cannot update, deactivate and remove the plugin.
- Because exploitation may yield code execution, sites that ran a vulnerable version on a public checkout should be checked for unexpected files (especially `.php` and other executable types) in the uploads directory and for signs of compromise.

**Plugin & theme developers / agencies**
- Audit client sites and site inventories for this plugin, and for the version installed.
- No API, hook, or deprecation changes are documented in the advisory; the action is purely to patch.

**Hosting & platform teams**
- Consider WAF rules or upload-directory execution restrictions (deny PHP execution under `wp-content/uploads`) as defense in depth while patching.

**Headless & REST consumers**
- Not documented as specific to REST; the advisory names only the `mipl_wc_upload_file` function.

## Technical details

The advisory identifies the flaw as CWE-434 (Unrestricted Upload of File with Dangerous Type) in the `mipl_wc_upload_file` function, which lacks file type validation and is reachable by unauthenticated users. The record does not describe the exact entry point (e.g. which AJAX action or route invokes it), the upload destination, or the diff of the fix, so those details cannot be stated here.

Note a discrepancy in the source: the description text says versions up to and including 1.2.1 are affected, while the affected-software list and metadata say <= 1.2.2, with 1.2.3 as the patched release. Treat 1.2.2 as vulnerable and target 1.2.3 or newer.

The patched version is expected to add file type validation to the upload handler, but the record does not show the specific validation used.
