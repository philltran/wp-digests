# GiveWP – Donation Plugin and Fundraising Platform <= 4.16.7.1 - Unauthenticated PHP Object Injection to Remote Code Execution

- **Type:** Vulnerability
- **Published:** 2026-08-28

- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-502: Deserialization of Untrusted Data
- **Affected:** GiveWP – Donation Plugin and Fundraising Platform (plugin) <= 4.16.7.1
- **Patched in:** 4.16.7.2

- **Usefulness:** 5/5

## Summary

GiveWP through 4.16.7.1 has an unauthenticated PHP Object Injection that chains to remote code execution. An attacker can register a donor account through GiveWP's registration handler and store a serialized object in the `last_name` profile field. The legacy donation flow then preserves that object in the GiveWP session, and a later request unserializes the session without restricting allowed classes. A usable POP chain through TCPDF and GiveWP's `ProviderForwarder` trait allows arbitrary OS command execution. The fix is in 4.16.7.2.

## Impact

- **Site owners:** Critical (CVSS 9.8), unauthenticated, and exploitable to full command execution. Update GiveWP to 4.16.7.2 or later immediately.
- **Exposure by version:**
  - 4.16.6 through 4.16.7.1: exploitation also needs a publicly obtainable registration nonce and a legacy or option-based donation form.
  - Earlier affected releases: reachable with only a published donation form and an active payment gateway.
- **Agencies and hosting/platform teams:** Audit all client sites running GiveWP and prioritise those with published legacy or option-based donation forms. The advisory does not describe indicators of compromise. Sites that were exposed before patching may warrant checking for unexpected donor accounts whose `last_name` contains serialized data, as well as the usual post-compromise review.
- **Plugin and theme developers:** No API change is documented. Anything that extends GiveWP sessions or donor profile handling should not assume the fix is complete for its own code paths.
- **Headless/REST consumers:** The advisory does not mention REST routes, so no specific guidance can be given.

## Technical details

The advisory describes the following chain (no diff or patch was provided, so the specific code changes in 4.16.7.2 are not described here):

1. **Injection:** An unauthenticated attacker uses GiveWP's registration handler to create a donor account and puts a serialized object payload in the `last_name` profile field.
2. **Persistence:** The legacy donation process preserves that donor data, including the serialized object, in the GiveWP session.
3. **Trigger:** A subsequent request unserializes the session without restricting permitted classes (no `allowed_classes` restriction), which is the CWE-502 flaw.
4. **Gadget chain:** A POP chain involving TCPDF and GiveWP's `ProviderForwarder` trait reaches arbitrary operating-system command execution.

On 4.16.6–4.16.7.1 the registration step requires a publicly obtainable registration nonce and a legacy or option-based form. Earlier releases need only a published donation form and an active payment gateway.

The advisory says only that the fix is in 4.16.7.2 and does not say whether it restricts unserialization, sanitizes the field, or removes the gadget.
