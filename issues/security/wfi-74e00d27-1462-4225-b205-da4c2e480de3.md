- **Usefulness:** 5/5

## Summary

JetEngine, Crocoblock's dynamic-content plugin, has an unauthenticated remote code execution flaw in versions up to and including 3.8.14. User-supplied input reaches a code-execution sink without sufficient validation, so an unauthenticated attacker can run arbitrary code on the server. The fix ships in 3.8.14.1.

## Impact

- **Site owners / hosting:**
  - Any site running JetEngine <= 3.8.14 is exposed to unauthenticated full server compromise (CVSS 9.8).
  - Update to 3.8.14.1 or later immediately.
  - If the site was exposed while unpatched, consider reviewing it for signs of compromise (unexpected PHP files, new admin users, modified plugins/themes) and rotating credentials and secrets such as `wp-config.php` salts and database credentials.
- **Plugin & theme developers / agencies:** Audit managed client sites and update any that run JetEngine. Check whether any custom code or add-ons depend on a specific JetEngine version before rolling out the update.
- **Platform teams:** Consider WAF rules or virtual patching as a stopgap where immediate updates are not possible. The advisory does not describe the vulnerable endpoint, so any rule would have to be generic.
- **Headless & REST consumers:** The advisory does not say whether the vulnerable path is a REST route, an AJAX handler, or something else, so do not assume headless setups are unaffected.
- **Breaking changes:** None documented; the advisory lists no deprecated or removed APIs.

## Technical details

The advisory is brief. It classifies the flaw as CWE-94 (code injection): user-supplied input is insufficiently validated before being executed, and no authentication is required to reach it. The record does not name the vulnerable function, file, hook, endpoint, or parameter, and it provides no diff or patch details.
