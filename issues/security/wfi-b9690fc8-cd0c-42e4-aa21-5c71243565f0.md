- **Usefulness:** 5/5

## Summary

The Frontegg SAML SSO plugin (<= 1.0.1) does not verify SAML signatures on incoming assertions. An unauthenticated attacker can forge a SAML response and log in as any existing user, including administrators. No patched version is available.

## Impact

- **Site owners using Frontegg SAML SSO:** Any site with the plugin active is exposed to full administrative takeover without credentials (CVSS 9.8). Because no patch exists, the record recommends weighing mitigations against your risk tolerance and notes that uninstalling and replacing the plugin may be the best option.
- **Agencies and platform teams:** Audit managed sites for this plugin (`wp plugin list | grep -i frontegg`). Deactivate it, or block the SAML login/ACS endpoint at the WAF or web server, until a replacement is in place. Because forged logins can look like ordinary SSO sessions, review admin user lists, recent logins, and new or modified accounts and plugins for signs of compromise.
- **Plugin and theme developers:** No API changes. This is a reminder that any custom SAML implementation must validate assertion signatures.
- **Headless and REST consumers:** No specific guidance in the record. A compromised admin session would give access to authenticated REST routes.

## Technical details

The record states that the plugin does not verify SAML signatures. A SAML service provider is supposed to validate the XML signature on the response or assertion against the identity provider's trusted certificate before trusting the asserted identity. Without that check, the assertion is attacker-controlled, so a crafted response naming any existing user (such as an administrator) is accepted and a session is established. The weakness is classified as CWE-288 (Authentication Bypass Using an Alternate Path or Channel).

The record does not name the affected files, functions, or endpoints, and I have not assumed them. No fixed version exists, so there is no diff to describe.
