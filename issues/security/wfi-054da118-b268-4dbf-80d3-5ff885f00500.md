- **Usefulness:** 5/5

## Summary

The Login Social plugin allows an unauthenticated attacker to take over an arbitrary WordPress account, including administrator accounts, by changing the target user's password. The root cause is missing identity validation before the plugin updates user details such as the password. Because no known patch is listed, the practical response is to remove or replace the plugin if it is installed.

## Impact

- **Site owners:** If Login Social is active, treat this as critical; an unauthenticated attacker can change any user's password and log in as that user.
- **Plugin & theme developers:** No core WordPress API change is described, but any social-login or account-linking flow must verify the authenticated user's identity before updating profile fields or passwords.
- **Hosting & platform teams:** Audit sites for the plugin, disable or uninstall it, force password resets for affected accounts, and review authentication logs for unauthorized password changes.
- **Headless & REST consumers:** No API change is described; if the plugin exposes endpoints, treat them as untrusted until the plugin is removed.

## Technical details

The advisory describes a missing authorization check in the plugin's user-detail update path. An unauthenticated request can update a user's details, including the password, without proving that the requester is the target user or otherwise has permission. The record does not name the specific file, function, hook, REST route, or parameter, so no exact code-level patch can be derived from it. The behavior is an unverified password change leading to account takeover.
