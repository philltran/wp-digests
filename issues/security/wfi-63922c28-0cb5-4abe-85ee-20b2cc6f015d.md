## Summary

The Demi – One Click Demo Import, Backup & Site Migration plugin contained a critical unauthenticated arbitrary directory deletion vulnerability (CVE-2026-14490) in versions up to 0.0.7. The flaw allowed attackers to recursively delete arbitrary server directories by exploiting the `demi_restore_step` AJAX endpoint, which bypassed standard WordPress capability and nonce checks when an attacker possessed an exposed HMAC signing key. The vulnerability has been patched in version 0.0.9 by restricting the AJAX handler to authenticated requests, enforcing strict path canonicalization and allow-listing, and securing the storage of signing keys and restore tokens.

## Impact

- **Site owners & administrators:** Update the Demi plugin to version 0.0.9 or newer immediately. Unpatched sites are vulnerable to unauthenticated directory deletion, which can cause data loss or site compromise.
- **Plugin & theme developers:** No direct code changes required for third-party developers, but audit any custom integrations with Demi’s `demi_restore_step` AJAX action or `CleanDir::execute()` method.
- **Hosting & platform teams:** Monitor for anomalous directory deletion activity or unexpected `demi_restore_step` AJAX calls from unauthenticated IPs. Consider blocking the endpoint at the WAF level until patches are applied.
- **No action required** for sites that have already updated to 0.0.9+ or do not use the Demi plugin.

## Technical details

The vulnerability originated from the `demi_restore_step` AJAX action being registered for unauthenticated access and accepting an on-disk HMAC signing key as a valid authentication substitute. The plugin stored this key and per-step restore tokens as dotfiles in a publicly accessible uploads subdirectory without `.htaccess` or index file protection, allowing attackers to retrieve them. Once obtained, an attacker could forge a signed state envelope and pass a raw absolute path to `CleanDir::execute()`, which lacked path canonicalization or allow-list validation, resulting in recursive deletion. The patch in 0.0.9 resolves the issue by restricting the AJAX handler to authenticated requests, removing the on-disk key bypass, enforcing path normalization and allow-listing on directory targets, and moving signing keys/tokens to non-public storage with proper directory protection.
