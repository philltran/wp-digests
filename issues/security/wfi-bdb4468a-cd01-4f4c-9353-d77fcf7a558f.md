# Shared Files Pro < 1.7.68 & Shared Files Free  < 1.7.67 - Unauthenticated Arbitrary File Deletion

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-08-28
- **CVE:** [CVE-2026-12513](https://www.cve.org/CVERecord?id=CVE-2026-12513)
- **CVSS:** 9.1 (Critical)
- **CWE:** CWE-22: Improper Limitation of a Pathname to a Restricted Directory ('Path Traversal')
- **Affected:** Shared Files – File Upload & Download Manager (plugin) < 1.7.67, Shared Files Pro (plugin) < 1.7.68
- **Patched in:** 1.7.67, 1.7.68
- **Researchers:** Huynh Kien Minh
- **Link:** [https://www.wordfence.com/threat-intel/vulnerabilities/id/bdb4468a-cd01-4f4c-9353-d77fcf7a558f](https://www.wordfence.com/threat-intel/vulnerabilities/id/bdb4468a-cd01-4f4c-9353-d77fcf7a558f)
- **Usefulness:** 5/5

## Summary

The Shared Files plugin (Free and Pro) failed to sufficiently validate file paths before deleting files, allowing unauthenticated attackers to delete arbitrary files on the server. Deleting a critical file such as `wp-config.php` can lead to remote code execution, for example by forcing the site back into the installer. The fix is in Shared Files 1.7.67 (Free) and Shared Files Pro 1.7.68.

## Impact

**Site owners**
- Update Shared Files – File Upload & Download Manager to 1.7.67 or later, and Shared Files Pro to 1.7.68 or later. The flaw is exploitable without authentication, so treat this as urgent.
- Sites that ran a vulnerable version should check for unexpectedly missing files (notably `wp-config.php`, `.htaccess`, and plugin or theme files) and review access logs for suspicious requests to the plugin's endpoints.

**Plugin & theme developers / agencies**
- Audit client sites and managed fleets for either plugin below the patched versions.
- If your code integrates with or extends Shared Files, no API changes are described in the advisory.

**Hosting & platform teams**
- A WAF rule or virtual patch may be a stopgap where immediate updates aren't possible. The advisory gives no endpoint or parameter details to build one from.

**Headless & REST consumers**
- The advisory does not say whether the vulnerable code is reachable through REST, AJAX, or a front-end handler, so don't assume headless setups are unaffected.

## Technical details

The advisory classifies this as CWE-22 (path traversal): the plugin's file deletion logic does not adequately validate the supplied file path, so an attacker can reference files outside the intended upload directory. The deletion path is reachable without authentication or capability checks. CVSS is 9.1 (Critical).

The advisory does not name the vulnerable function, file, endpoint, or parameter, and no diff or patch is provided, so the exact fix is not documented here. The stated remediation is upgrading to the patched releases. Note that the advisory text is internally inconsistent about version boundaries (it mentions "up to 1.7.68 (exclusive - pro) and 1.7.67 (free - pro)"); the structured affected-software data specifies Free < 1.7.67 and Pro < 1.7.68.
