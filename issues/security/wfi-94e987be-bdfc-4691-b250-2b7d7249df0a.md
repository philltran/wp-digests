# 6Storage Rentals <= 2.27.0 - Unauthenticated Account Takeover via 'email' Parameter

- **Type:** Vulnerability

- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-287: Improper Authentication
- **Affected:** 6Storage Rentals (plugin) <= 2.27.0
- **Researchers:** Afan, moonge
- **Link:** [https://www.wordfence.com/threat-intel/vulnerabilities/id/94e987be-bdfc-4691-b250-2b7d7249df0a](https://www.wordfence.com/threat-intel/vulnerabilities/id/94e987be-bdfc-4691-b250-2b7d7249df0a)
- **Usefulness:** 5/5

## Summary

The 6Storage Rentals plugin exposes an unauthenticated account takeover flaw in the `six_storage_create_wp_user()` AJAX handler. The handler is reachable without authentication and can establish a session for any WordPress user whose email address is supplied. This allows an attacker to log in as an existing account, including an administrator, without credentials.

## Impact

- **Site owners:** Unauthenticated attackers can take over any existing WordPress account, including administrators, by submitting the target user's email address.
- **Plugin users:** No known patch is available; the advisory recommends uninstalling the affected plugin and finding a replacement.
- **Hosting and platform teams:** Because the exposed endpoint is unauthenticated, affected sites should remove or replace the plugin rather than relying on a patch.

## Technical details

The vulnerable flow is the `six_storage_create_wp_user()` handler registered for `wp_ajax_nopriv_six_storage_create_wp_user`. The handler performs no nonce, capability, credential, or ownership verification before resolving a WordPress user from the attacker-supplied `email` value and then calling `wp_set_current_user()` and `wp_set_auth_cookie()`. As a result, the request can create an authenticated session for the resolved user without any prior authentication.
