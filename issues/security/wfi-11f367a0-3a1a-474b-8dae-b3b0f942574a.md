## Summary

JetFormBuilder (Dynamic Blocks Form Builder) contained an unauthenticated arbitrary shortcode execution flaw. Request-supplied message content was passed through shortcode expansion before escaping was applied. In addition, `sanitize_wysiwyg()` called `wp_kses_post()` before `wp_specialchars_decode()`, so entity-encoded payloads survived sanitization and were decoded just in time for shortcode parsing. An unauthenticated attacker can inject shortcode syntax into form message content that is displayed on any page rendering a JetFormBuilder form. The issue is fixed in 3.6.5.2.

## Impact

**Site owners**
- Update JetFormBuilder to 3.6.5.2 or later as soon as possible. The issue is rated critical and requires no authentication.
- Any shortcode registered on the site is reachable by an attacker, so the real-world impact depends on which plugins and themes are active. The record classifies it as Remote Code Execution (CWE-94).

**Plugin & theme developers / agencies**
- Audit registered shortcodes on sites running JetFormBuilder. Shortcodes that perform privileged actions, include files, query data, or output sensitive values are the most dangerous when they can be triggered by anonymous visitors.

**Hosting & platform teams**
- Consider prioritizing the update across managed fleets. No configuration or migration is required beyond the plugin update. The record does not describe a workaround or a WAF rule.

## Technical details

The advisory identifies two combined defects. No diff or patch was provided, so the following is based only on the advisory text:

1. **Shortcode expansion before escaping.** Unsanitized, request-supplied message content was passed through shortcode expansion (`do_shortcode`-style processing) before any escaping was applied.
2. **Incorrect sanitization order in `sanitize_wysiwyg()`.** The function ran `wp_kses_post()` first and `wp_specialchars_decode()` second. Entity-encoded payloads (for example, encoded brackets) are not recognized as shortcode syntax by KSES, pass through intact, and are then decoded into live shortcode markup. That markup is subsequently parsed as a shortcode.

The resulting shortcode is executed when the message content is displayed on any page that renders a JetFormBuilder form. An illustrative sketch of the ordering problem (not taken from the plugin source):

```php
// Vulnerable ordering (as described)
$content = wp_kses_post( $input );          // entity-encoded payload passes
$content = wp_specialchars_decode( $content ); // decoded into [shortcode ...]
// ...later: shortcode expansion runs on $content
```

The exact code paths, file names, and the specific fix in 3.6.5.2 are not included in the source record.
