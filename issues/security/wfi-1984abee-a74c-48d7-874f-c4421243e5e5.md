## Summary

WordPress core's `wpautop()` contains a stored XSS flaw that unauthenticated users can exploit through comment content. The paragraph-unwrapping regex `<p><blockquote([^>]*)>` does not handle a `<blockquote>` whose attribute region contains a `>`. When this combines with `wpautop()`'s blank-line paragraph splitting, a newline inside a blockquote `cite` value causes a `<p>` tag to be moved into the tag itself. The resulting malformed markup lets attacker-supplied script run when the comment is rendered.

## Impact

**Site owners / hosting & platform teams**
- Update core to the patched release for your branch. The fix was shipped as security releases across all supported branches.
- Exploitation needs no authentication and goes through comment submission. If comments are moderated, the payload is stored but only renders after an approver publishes it.
- Review pending and recently approved comments for unusual `<blockquote cite="…">` markup that contains `>` characters or embedded newlines.
- Sites with comments closed have a reduced exposure through this vector.

**Plugin & theme developers**
- If your code runs `wpautop()` on untrusted input, it goes through the same vulnerable path. Examples include custom comment renderers, front-end submission forms, and user bios.
- The advisory does not describe any API change. No code changes are required beyond running a patched core.

**Headless & REST consumers**
- Rendered comment HTML produced by core formatting is affected until core is patched. Do not treat pre-rendered HTML as trusted.

## Technical details

The bug is in `wpautop()` (`wp-includes/formatting.php`), specifically the step that removes a `<p>` wrapped around an opening blockquote:

```
<p><blockquote([^>]*)>
```

The capture group `([^>]*)` assumes the attribute region never contains a literal `>`. An attacker can supply a `cite` attribute value that contains a `>`, so the regex treats the tag as ending early.

`wpautop()` also splits paragraphs on blank lines. A newline placed inside the `cite` value therefore produces a paragraph boundary *inside* the tag. When the unwrap/rewrap steps run, a `<p>` tag ends up relocated into the blockquote's attribute area. The browser then parses the result so that attacker-controlled content escapes the attribute context, and script can execute.

The advisory names comment content as the unauthenticated delivery vector. It does not describe the exact patch contents, so the precise shape of the corrected regex or handling is not documented in this record.
