# Total Donations <= 2.0.5 - Unauthenticated SQL Injection

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-08-19
- **CVE:** [CVE-2026-73391](https://www.cve.org/CVERecord?id=CVE-2026-73391)
- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-89: Improper Neutralization of Special Elements used in an SQL Command ('SQL Injection')
- **Affected:** Total Donations (plugin) <= 2.0.5
- **Researchers:** Tran Nguyen Bao Khanh
- **Link:** [https://www.wordfence.com/threat-intel/vulnerabilities/id/0c3ecf70-544f-49c1-a943-86df89685b58](https://www.wordfence.com/threat-intel/vulnerabilities/id/0c3ecf70-544f-49c1-a943-86df89685b58)
- **Usefulness:** 5/5

## Summary

The Total Donations plugin contains an unauthenticated SQL injection in all versions up to and including 2.0.5. A user-supplied parameter is insufficiently escaped and the affected SQL query is not prepared, so an attacker can append additional SQL to the existing query and extract data from the database. No patched version is available.

## Impact

**Site owners**
- Any site running Total Donations <= 2.0.5 is exposed to unauthenticated database extraction (CVSS 9.8, Critical). No login or special privileges are required.
- Because the plugin handles donations, the database may hold donor data alongside core WordPress tables (users, password hashes, options), all of which are reachable through SQL injection.
- **No patch exists.** Wordfence's guidance is to review the details and apply mitigations based on risk tolerance, and notes it may be best to uninstall the plugin and find a replacement.

**Agencies / hosting & platform teams**
- Inventory client sites for the `Total Donations` plugin and treat every installed copy as vulnerable.
- Interim options: deactivate and remove the plugin, replace it with a maintained donation plugin, or apply WAF rules that block SQL injection payloads against the plugin's endpoints. The source does not identify the vulnerable parameter or endpoint, so WAF rules cannot be tuned to it from this record.
- If the plugin has been exposed, consider reviewing logs and database access for signs of exploitation and rotating credentials; the record itself does not report active exploitation.

**Plugin developers**
- Nothing to change unless you maintain or fork this plugin. The general lesson is to pass user input through `$wpdb->prepare()` rather than concatenating it into queries.

## Technical details

The source record gives limited detail. It classifies the flaw as CWE-89 (SQL injection) and attributes it to insufficient escaping of a user-supplied parameter combined with a lack of sufficient preparation of an existing SQL query (i.e. the query is not built with `$wpdb->prepare()`). This lets an unauthenticated attacker append additional SQL to the existing query and extract sensitive information.

The record does not name the vulnerable parameter, file, function, AJAX action, or REST route, and no fixed version or diff is available, so no more specific code-level description can be given.
