# Multi Uploader for Gravity Forms <= 1.1.8 - Missing Authorization to Unauthenticated Arbitrary Media Deletion

## Summary

The Multi Uploader for Gravity Forms plugin (≤ 1.1.8) contained a critical authorization flaw allowing unauthenticated attackers to permanently delete any WordPress media attachment. The vulnerability stemmed from a missing capability check in the AJAX handler, combined with a CSRF nonce that was inadvertently exposed to the public via a JavaScript object. The issue was resolved in version 1.1.9 by enforcing proper capability verification and restricting nonce exposure.

## Impact

- **Plugin users & site owners**: Sites running Multi Uploader for Gravity Forms ≤ 1.1.8 are vulnerable to arbitrary media deletion. Update to 1.1.9 or later immediately.
- **Plugin & theme developers**: No direct code changes required unless you are maintaining a custom fork or integrating the plugin's uploader component directly.
- **Hosting & platform teams**: Monitor for mass `wp_delete_attachment` calls or unusual AJAX traffic targeting `gfmu_delete_file` endpoints on affected sites.
- No configuration migration is needed; the fix is a straightforward plugin update.

## Technical details

The vulnerability resided in the `plupload_ajax_delete_file()` function, which was exposed to unauthenticated requests via the `wp_ajax_nopriv_gfmu_delete_file` action hook. The function lacked a capability check before processing the deletion request. Additionally, the CSRF nonce required for the operation was serialized into the `GFMU_options` JavaScript object on any page rendering a multi-uploader form, effectively bypassing CSRF protections. Patching in 1.1.9 introduces a capability verification step within `plupload_ajax_delete_file()` and removes or scopes the nonce exposure so it is no longer globally accessible in client-side scripts.
