# Hash Form – Drag & Drop Form Builder <= 1.4.2 - Unauthenticated Arbitrary File Upload

- **Patched in:** 1.4.3

- **Usefulness:** 5/5

## Summary

The Hash Form – Drag & Drop Form Builder plugin fails to validate file types on upload in versions up to and including 1.4.2. Unauthenticated attackers can upload arbitrary files to the server, which may lead to remote code execution. The issue is fixed in 1.4.3.

## Impact

**Site owners**
- Any site running Hash Form <= 1.4.2 is exposed to unauthenticated arbitrary file upload (CVSS 9.8, Critical). Update to 1.4.3 or later immediately.
- If the plugin was active and reachable on a vulnerable version, check for unexpected files (e.g. `.php` or other executable types) in the uploads directory and review access logs for anomalous requests to the plugin's upload handling.

**Plugin & theme developers / agencies**
- Audit client sites and any code bundles or starter stacks that include Hash Form; pin or update to >= 1.4.3.
- No API changes or migration steps are described in the advisory; the action is to update.

**Hosting & platform teams**
- Consider a virtual-patch or WAF rule and disabling PHP execution in the uploads directory as defense in depth until sites are updated.

## Technical details

The advisory states the root cause is missing file type validation in the plugin's upload handling, classified as CWE-434 (Unrestricted Upload of File with Dangerous Type). No authentication is required to reach the vulnerable code path. The advisory does not name the specific function, AJAX action, REST route, or file involved, and no diff or patch details were provided, so the exact fix in 1.4.3 (e.g. extension allow-listing or use of `wp_check_filetype_and_ext()`) cannot be confirmed from the source material. Uploading a server-executable file into a web-accessible location is what makes RCE possible.
