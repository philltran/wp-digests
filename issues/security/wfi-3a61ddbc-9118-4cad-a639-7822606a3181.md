# TrueBooker <= 1.2.3 - Missing Authorization to Unauthenticated Arbitrary User Email Modification via 'admin_addcustomer' AJAX Action

- **Patched in:** 1.2.4

## Summary

TrueBooker (Appointment Booking and Scheduler System) <= 1.2.3 exposes an `admin_addcustomer` AJAX action that lacks an authorization check. An unauthenticated attacker can change the email address of any existing user account, including administrators. Because the email can be redirected to an attacker-controlled address, the attacker can trigger a password reset and take over the account. The issue is fixed in 1.2.4.

## Impact

- **Site owners:**
  - Any site running TrueBooker <= 1.2.3 is exposed to unauthenticated administrator account takeover (CVSS 9.8, Critical). Update to 1.2.4 or later immediately.
  - Review administrator and other privileged accounts for unexpected email address changes, and check for unexpected password reset emails or logins. The advisory does not describe indicators of compromise, so this is a precaution.
  - If you cannot update immediately, deactivating the plugin removes the exposure. The advisory itself only recommends updating.
- **Plugin & theme developers / agencies:** Audit client sites for the plugin and its version. Any code that registers `wp_ajax_nopriv_*` handlers should perform a capability check and nonce verification.
- **Hosting & platform teams:** Requests to `admin-ajax.php` with `action=admin_addcustomer` from unauthenticated sessions are a candidate signal for WAF rules or log review. The advisory does not describe exploit traffic, so this is inferred from the action name.
- **Headless & REST consumers:** No REST route is mentioned. The vector is the AJAX action.
