## Summary

Aimogen Pro versions ≤ 2.8.4 contain an unauthenticated privilege escalation vulnerability in the `aiomatic_call_google_ai_function` callback. The function lacks a capability check, allowing unauthenticated attackers to invoke the `aimogen_wp_god_mode` tool, bypass internal function blacklists, and execute arbitrary PHP code—including creating new administrator accounts. Updating to 2.8.5 enforces proper access controls and closes this execution path.

## Impact

- **Site owners & administrators:** Unauthenticated attackers can escalate to admin privileges or execute arbitrary PHP. Immediate update to 2.8.5 is required.
- **Plugin & theme developers:** No direct API changes, deprecations, or migration steps; this is a security patch for a third-party plugin.
- **Hosting & platform teams:** Monitor for exploitation attempts targeting the `aiomatic_call_google_ai_function` endpoint and consider WAF rules to block unauthenticated calls to this handler.
- **Action required:** Update Aimogen Pro to ≥ 2.8.5 immediately. No code changes needed for sites using the plugin.

## Technical details

The vulnerability stems from a missing capability check on the `aiomatic_call_google_ai_function` callback. In affected versions, unauthenticated requests can trigger the `aimogen_wp_god_mode` tool, which clears function blacklists and passes arbitrary strings to PHP for execution. Patch 2.8.5 introduces the required capability verification to the callback, restricting tool invocation and function execution to authenticated users with appropriate permissions. The fix does not alter the plugin's public block schemas, REST routes, or hook signatures; it strictly enforces access control on the existing callback.
