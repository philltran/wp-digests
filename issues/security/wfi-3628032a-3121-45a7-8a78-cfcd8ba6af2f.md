## Summary

The Pods plugin had an unauthenticated privilege escalation vulnerability in its `pods_admin` AJAX router. Access checks were funneled through `pods_error()`, which under the JSON meta-box-loader compatibility path only wrote failures to the PHP error log and returned `false` instead of terminating the request. As a result, the method allowlist, nonce verification, login enforcement, and capability gate did not block requests, allowing an unauthenticated attacker to reach admin methods, escalate to Administrator, or overwrite any user's password. The fix restores request termination when authorization checks fail.

## Impact

- **Site owners:** Update the Pods plugin to a patched release immediately; this is a critical unauthenticated takeover risk.
- **Plugin & theme developers:** No additional code changes are described in the advisory.
- **Hosting & platform:** Patch all affected installs.
- **Headless & REST consumers:** No headless- or REST-specific impact is described.

## Technical details

The vulnerable behavior is in the `pods_admin` AJAX router. Every access check — method allowlist, nonce verification, login enforcement, and capability gate — was routed through `pods_error()`. Under the JSON meta-box-loader compatibility path, `pods_error()` only wrote failures to the PHP error log and returned `false`, so the request continued instead of being terminated. The patch changes the failure path so that failed authorization checks stop the request.
