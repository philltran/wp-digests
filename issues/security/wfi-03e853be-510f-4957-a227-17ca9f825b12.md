# Drag and Drop File Upload for Elementor Forms <= 1.6.0 - Unauthenticated Arbitrary File Upload via 'type' Parameter

- **Affected:** Drag and Drop File Upload for Elementor Forms (plugin) <= 1.6.0
- **Patched in:** 1.6.1

- **Usefulness:** 5/5

## Summary

The Drag and Drop File Upload for Elementor Forms plugin lets unauthenticated users upload arbitrary files, including PHP, through its `elementor_file_upload` handler in versions up to 1.6.0. `is_file_type_valid()` uses the attacker-supplied `type` parameter as regex keys in the MIME allowlist, so a crafted extension passes validation and `sanitize_file_name()` later normalizes it to an executable PHP extension. Version 1.6.1 fixes it.

## Impact

**Site owners**
- Any site running the plugin at <= 1.6.0 is exposed to unauthenticated upload of potentially executable files, which can lead to remote code execution (CVSS 9.8).
- Update to 1.6.1 or later. If the plugin cannot be updated immediately, deactivate it or block the upload endpoint at the WAF.
- Sites that ran a vulnerable version should check the upload directory used by the plugin for unexpected `.php` or other executable files, and treat any found as a sign of compromise.

**Plugin & theme developers / agencies**
- Audit client sites and maintenance fleets for this plugin and its installed version.
- If you write your own upload handlers, do not let client-supplied parameters drive the MIME or extension allowlist.

**Hosting & platform**
- Consider rules that block PHP execution in upload directories and flag requests to the plugin's upload action.

## Technical details

The source record names the vulnerable path as `elementor_file_upload`, which calls `is_file_type_valid()`. That function uses the attacker-controlled `type` parameter as regex keys in the MIME allowlist check, so the client influences which patterns are tested instead of the allowlist being fixed server-side.

This enables a bypass of the extension check. An attacker submits a crafted extension that passes validation, and `sanitize_file_name()` later normalizes it into a PHP extension, so the stored file is executable. The weakness is classified as CWE-434 (unrestricted upload of a file with a dangerous type). No authentication or nonce requirement is described as blocking the request.

The record does not include a diff or describe the exact code change in 1.6.1, so the specifics of the fix are not known from the source. The general remediation pattern is to validate against a server-defined allowlist and to check the extension after sanitization, not before.
