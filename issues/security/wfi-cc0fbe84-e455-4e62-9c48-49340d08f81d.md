# Invoice Generator <= 1.0.0 - Unauthenticated Account Takeover via Weak Password Reset Validation via 'reset_user_id' Parameter

- **Usefulness:** 5/5

## Summary

The Invoice Generator plugin (≤ 1.0.0) contains a critical unauthenticated account takeover vulnerability in its password reset flow. The `pravel_invoice_change_password()` AJAX handler lacks nonce verification and capability checks, and uses a loose equality comparison that trivially passes when the `reset_activation_code` parameter is omitted. This allows attackers to supply an arbitrary `reset_user_id` and force a password change for any account, including administrators.

## Impact

- **Site owners & administrators**: Any site running Invoice Generator ≤ 1.0.0 is immediately vulnerable to full account takeover without authentication.
- **Plugin developers & agencies**: If this plugin is in use, it must be disabled or uninstalled immediately. No patch is currently available.
- **Hosting & platform teams**: Monitor for requests to the `nopriv` AJAX endpoint handling `pravel_invoice_change_password()` and consider blocking the endpoint at the WAF level until the plugin is updated or removed.
- **Required action**: Disable or uninstall the plugin immediately. No code migration is possible without a vendor patch.

## Technical details

The vulnerability resides in the `pravel_invoice_change_password()` function, which is registered as a `nopriv` AJAX handler. The handler accepts a `reset_user_id` POST parameter to target a specific account and compares the incoming `reset_activation_code` against the user's `forgot_email` meta using loose equality (`==`). Because the function performs no nonce validation or capability verification, an attacker can omit `reset_activation_code` entirely. This causes the comparison to evaluate `'' == ''`, which always returns true for users who have never triggered a password reset. The handler then proceeds to set the target account's password to the attacker-supplied value.
