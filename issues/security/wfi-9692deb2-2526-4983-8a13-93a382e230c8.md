# Divi Form Builder <= 5.1.8 - Unauthenticated Arbitrary File Upload Leading to Remote Code Execution via 'acceptFileTypes' Parameter

- **Usefulness:** 5/5

## Summary

Divi Form Builder versions up to 5.1.8 contain an unauthenticated arbitrary file upload vulnerability that enables remote code execution. The `do_image_upload()` function directly interpolates the `acceptFileTypes` POST parameter into a regular expression for file extension validation, allowing attackers to bypass extension checks and upload executable PHP variants such as `.phtml`, `.phar`, `.php5`, or `.php7`. The vulnerability was fully remediated in version 5.1.9 by replacing the dynamic regex interpolation with a strict extension allowlist and enforcing server-side MIME validation before writing files to disk.

## Impact

- **Site owners & administrators:** Update Divi Form Builder to 5.1.9 or later immediately. Unauthenticated attackers can achieve RCE if the plugin is active.
- **Hosting & platform teams:** Nginx-based environments are fully exposed because the plugin’s `.htaccess` protection only blocks `.php` extensions and is ignored by Nginx. Consider temporarily blocking the `/wp-content/uploads/de_fb_uploads/` directory for non-authorized uploads until patched.
- **Plugin & theme developers:** No direct code changes required, but audit custom integrations that rely on the plugin’s upload endpoints or nonce handling.
- **Action required:** Update to 5.1.9. No migration or configuration changes needed beyond the standard plugin update.

## Technical details

The vulnerability resides in the `do_image_upload()` function, where the `acceptFileTypes` POST parameter is interpolated directly into a regex used to whitelist uploaded file extensions. This allowed payloads like `.phtml`, `.phar`, `.php5`, or `.php7` to pass validation and be written to the publicly accessible `/wp-content/uploads/de_fb_uploads/` directory. The existing `.htaccess` rule only blocked `.php` files, providing a false sense of security on Apache and no protection on Nginx. Patched in 5.1.9, the fix replaces the dynamic regex interpolation with a hardcoded allowlist of safe extensions and enforces server-side type checks before writing to disk. (The advisory notes a partial patch in 5.1.3 that did not fully address the regex interpolation or the Nginx bypass.)

## Contribution

The advisory record carries no public design debate or alternative implementation discussions; the remediation focused on replacing dynamic regex interpolation with a strict extension allowlist after an incomplete fix in 5.1.3.
