# WP images upload on piclect <= 1.0 - Unauthenticated Arbitrary File Upload

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-09-14
- **CVE:** [CVE-2026-84171](https://www.cve.org/CVERecord?id=CVE-2026-84171)
- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-434: Unrestricted Upload of File with Dangerous Type
- **Affected:** WP images upload on piclect (plugin) <= 1.0
- **Researchers:** João Ramos Maciel
- **Link:** [https://www.wordfence.com/threat-intel/vulnerabilities/id/b2ea5e77-335a-4f40-9a04-9e1d4f3e1017](https://www.wordfence.com/threat-intel/vulnerabilities/id/b2ea5e77-335a-4f40-9a04-9e1d4f3e1017)
- **Usefulness:** 5/5

## Summary

The WP images upload on piclect plugin, in all versions up to and including 1.0, accepts file uploads from unauthenticated users without validating file type. An attacker can place arbitrary files on the server, which may lead to remote code execution. No patched version is available.

## Impact

**Site owners**
- Any site running WP images upload on piclect <= 1.0 is exposed to unauthenticated arbitrary file upload (CVSS 9.8, Critical). Exploitation requires no account.
- There is **no known patch**. Wordfence's guidance is to review the details, apply mitigations based on your risk tolerance, and consider uninstalling the plugin and finding a replacement.
- Sites that have run the plugin should check the uploads directory and other web-writable paths for unexpected files, particularly executable types such as `.php`.

**Plugin & theme developers / agencies**
- Audit client sites and managed fleets for this plugin slug and remove or replace it where found.

**Hosting & platform teams**
- Where the plugin cannot be removed immediately, blocking execution of PHP in upload directories and filtering requests to the plugin's upload endpoint at the WAF or web server are possible stopgaps. The advisory does not describe specific mitigations, so treat these as general hardening rather than vendor-verified fixes.

## Technical details

The advisory attributes the flaw to missing file type validation (CWE-434: Unrestricted Upload of File with Dangerous Type) in the plugin's upload handling. The record does not name the vulnerable function, file, hook, or endpoint, and no code diff or patch is available, so the exact entry point is not documented here.

An unauthenticated request can cause an arbitrary file to be written to the server. If the file lands in a web-accessible, PHP-executable location, the result can be remote code execution. Affected range: all versions <= 1.0, with no fixed version.
