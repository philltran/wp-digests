# MyHome Core <= 4.4.5 - Authentication Bypass to Account Takeover via Activation Token

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-08-29
- **CVE:** [CVE-2026-15980](https://www.cve.org/CVERecord?id=CVE-2026-15980)
- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-289: Authentication Bypass by Alternate Name
- **Affected:** MyHome Core (plugin) <= 4.4.5
- **Patched in:** 4.4.6
- **Researchers:** Rafie Muhammad
- **Link:** [https://www.wordfence.com/threat-intel/vulnerabilities/id/c458e018-5901-4917-9847-35f07646e068](https://www.wordfence.com/threat-intel/vulnerabilities/id/c458e018-5901-4917-9847-35f07646e068)
- **Usefulness:** 5/5

## Summary

MyHome Core versions up to and including 4.4.5 allow unauthenticated attackers to take over unconfirmed user accounts, including administrators. The `send_link()` AJAX handler lacks an authorization check and lets anyone generate an activation token for an arbitrary unconfirmed account. The `activate()` function then validates that token improperly and issues a valid authentication cookie. Version 4.4.6 patches it.

## Impact

**Site owners**
- Update MyHome Core to 4.4.6 or later. The issue is rated Critical (CVSS 9.8) and is exploitable without authentication.
- Exposure requires a specific configuration: the MyHome theme in legacy/WPBakery mode, with frontend registration and confirmation email enabled. Sites not using that configuration are not described as exploitable.
- The target account must not already have the `myhome_agent_confirmed` user meta set. Per the advisory, this includes administrator accounts lacking that meta.
- If you ran an affected configuration, review recent logins and admin-level users for unexpected activity. The advisory does not describe indicators of compromise.

**Plugin & theme developers / agencies**
- Audit client sites for MyHome Core and check whether the legacy/WPBakery mode with frontend registration and confirmation email is enabled.

**Hosting & platform**
- Consider WAF or virtual-patching coverage for the `send_link()` AJAX action on sites that cannot update immediately. The advisory does not name the action or provide rules.

No code changes are needed beyond the plugin update.

## Technical details

The advisory gives two root causes and no code diff, so details are limited to what it states:

- **Missing authorization in `send_link()`**: this AJAX handler can be called by unauthenticated users and generates an activation token for an unconfirmed user account, with no check that the caller owns or may act on that account.
- **Improper token validation in `activate()`**: the token produced above is accepted, and the function sets a valid authentication cookie for the target account.

Combined, an attacker can request a token for a chosen unconfirmed account and immediately use it to log in as that user, including an administrator. The gating condition is that the account lacks the `myhome_agent_confirmed` user meta.

The CWE is classified as CWE-289 (Authentication Bypass by Alternate Name). The advisory does not describe the specific patch changes in 4.4.6, and the exact hook names, parameters, and token format are not given in the source.
