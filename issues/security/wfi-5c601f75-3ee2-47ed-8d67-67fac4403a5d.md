## Summary

The JSON Options plugin, in all versions up to and including 0.0.4, allows unauthenticated attackers to execute arbitrary code on the server. The advisory attributes this to insufficient validation of user-supplied input before it is executed (code injection). No patched version exists.

## Impact

- **Site owners:** Any site running JSON Options <= 0.0.4 is exposed to unauthenticated remote code execution, which typically means full site and server-account compromise. Because no patch is available, the practical options are to deactivate and delete the plugin and find a replacement, or to apply compensating controls based on your risk tolerance.
- **Plugin & theme developers / agencies:** Audit client sites and code for dependencies on this plugin. If it is in use, plan a migration away from it, and check for signs of compromise (unexpected files, new admin users, modified options or core files) on sites where it was active.
- **Hosting & platform teams:** Consider scanning fleets for this plugin slug and blocking or removing it. A WAF rule may help, but the advisory does not describe the attack vector, so any rule would be speculative.
- **Headless & REST consumers:** The advisory does not say which entry point is exposed, so no specific REST or AJAX route can be named as affected.
- **Breaking changes or API removals:** None. This is a vulnerability in a third-party plugin, not a change to core.

## Technical details

The advisory is brief. It classifies the flaw as CWE-94 (Improper Control of Generation of Code) and states that user-supplied input is insufficiently validated before being executed. It is exploitable without authentication and carries a CVSS of 9.8.
