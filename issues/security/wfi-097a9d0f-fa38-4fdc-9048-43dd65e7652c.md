# FormGent <= 1.9.2- Missing Authorization to Unauthenticated Arbitrary File Deletion via 'file_token' Parameter

## Summary

The FormGent plugin contained a critical missing authorization vulnerability that allowed unauthenticated attackers to delete arbitrary files via the `file_token` parameter on the `/wp-json/formgent/responses/attachments` REST endpoint. The issue stemmed from the route being registered without authentication middleware, which also permitted path traversal bypasses on systems where the plugin’s upload directory had not yet been created. This has been resolved in version 1.10.0 by enforcing proper capability checks and validating file paths before deletion.

## Impact

- **Site owners & administrators:** Must update FormGent to 1.10.0 or later immediately to prevent arbitrary file deletion and potential site takeover.
- **Plugin & theme developers:** No direct code changes required, but developers integrating with FormGent’s REST API should verify that any custom endpoints or file-handling logic implement proper authentication and path validation.
- **Hosting & platform teams:** Monitor for exploitation attempts targeting the `file_token` parameter on affected installations and ensure server-side WAF rules block unauthenticated DELETE requests to the affected REST route.
- **Action required:** Update the plugin to 1.10.0+; no migration or configuration changes are needed beyond the standard update process.

## Technical details

The vulnerability resides in `routes/rest/api.php`, where the `/wp-json/formgent/responses/attachments` REST route was registered without attaching authentication middleware or verifying user capabilities. The endpoint accepted a `file_token` parameter to identify files for deletion but failed to validate that the requesting user had permission to perform the operation. On Linux environments where `wp-content/uploads/formgent` does not exist by default, the path traversal protection could be bypassed, allowing an attacker to resolve arbitrary paths (e.g., `wp-config.php`) and trigger deletion. The patch in 1.10.0 introduces a capability check on the REST controller and enforces strict path resolution within the designated upload directory before executing the delete operation.

## Contribution

The issue was coordinated through responsible disclosure and resolved in version 1.10.0 by adding capability verification and path validation to the REST endpoint handler; the advisory record contains no further discussion of alternative remediation approaches or review debates.
