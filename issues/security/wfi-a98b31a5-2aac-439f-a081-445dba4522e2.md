## Summary

The SmilePass Selfie Login plugin, in all versions up to and including 1.0.2, contains an authentication bypass that lets unauthenticated attackers log in as arbitrary existing users, including administrators. No patched version is available. The source record does not describe the vulnerable code path.

## Impact

- **Site owners:**
  - Any site running SmilePass Selfie Login <= 1.0.2 is exposed to unauthenticated full account takeover, up to administrator, which typically means complete site compromise.
  - Because no patch exists, the practical options are to deactivate and delete the plugin and replace it with a different login mechanism, or to apply mitigations based on your own risk tolerance.
  - If the plugin was active, audit for unexpected administrator accounts, recent logins, changed passwords or emails, newly installed plugins or themes, and modified files.
- **Plugin & theme developers / agencies:** Inventory client sites for this plugin (for example with `wp plugin list`) and remove it where found. Consider rotating credentials and sessions for privileged users on affected sites.
- **Hosting & platform teams:** Flag or block the plugin across managed fleets. A WAF rule is only a stopgap, since the exact attack vector is not published in the source record.
- **Headless & REST consumers:** The record does not say which entry point (REST, AJAX, or a form handler) is affected, so do not assume headless setups are unaffected if the plugin is installed.

## Technical details

The source record gives only the classification: CWE-288 (Authentication Bypass Using an Alternate Path or Channel), CVSS 9.8. It states that unauthenticated attackers can log in as other users, but it does not name the vulnerable function, hook, endpoint, or parameter, and no diff or fix exists because no patch is available.
