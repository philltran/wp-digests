## Summary

The Events Calendar through 6.17.4 contains an unauthenticated PHP object injection that leads to remote code execution. The `is_safe_widget_instance` guard meant to protect widget deserialization can be bypassed, and `enable_rendering_widget_copied()` can forge a valid `wp_hash` integrity attribute before `unserialize()` runs. An unauthenticated commenter can deliver the payload through the plugin's V2 single-event template. The fix is in 6.17.4.1.

## Impact

**Site owners**
- Update The Events Calendar to 6.17.4.1 or later immediately. The issue is rated CVSS 9.8 and requires no authentication or approval.
- Exposure requires comments to be enabled and visible on events. Sites with event comments disabled are not reachable through the described path, but updating is still the correct action.
- Sites that had event comments enabled while on <= 6.17.4 should check for unexpected pending comments containing block markup, and for signs of post-exploitation activity such as unknown files or admin users.

- If you extend the plugin's widget-copy or block rendering paths, expect to re-test after updating.

**Hosting & platform teams**
- Consider virtual patching or WAF rules for comment submissions containing block-comment markup or serialized-object payloads until sites are patched.

## Technical details

The advisory describes a chain of three weaknesses (CWE-502). No diff or patched code is provided, so the specifics of the fix are not described.

1. **Injection point:** The plugin's V2 single-event template runs `do_blocks()` over buffered comment HTML. Block markup placed in a comment is therefore parsed and rendered as blocks.
2. **Delivery without moderation:** WordPress returns a moderation-hash URL that lets an unauthenticated commenter view their own pending comment immediately. The injected block markup reaches the vulnerable code path before any moderator approves it.
3. **Guard bypass:** `is_safe_widget_instance` is meant to reject unsafe serialized widget instances, but it can be bypassed because PHP fires magic methods during its pre-parse. In addition, `enable_rendering_widget_copied()` forges a valid `wp_hash` integrity attribute, so the integrity check passes before `unserialize()` is reached.

The result is attacker-controlled `unserialize()` input, which yields PHP object injection and, through an available gadget chain, code execution on the server. The advisory does not name the gadget chain.

Patched version: 6.17.4.1.
