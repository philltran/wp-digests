## Summary

WordPress core had a stored XSS vulnerability in the custom header feature. The `header_image_data` theme mod's width, height, and URL values were not sanitized strictly enough. `get_custom_header()` returned `width`/`height` without casting them to integers, and `Custom_Image_Header::step_1()` echoed a `style` attribute string without escaping it. A user with `edit_theme_options` could therefore store script payloads that execute on the custom-header admin screen. The patched releases fix both problems.

## Impact

**Site owners / hosting & platform**
- Update to the patched point release for your branch. Minor auto-updates on supported branches should deliver it; confirm they are not disabled.
- The main risk is on **Multisite**. There, site administrators have `edit_theme_options` but lack `unfiltered_html`, so this was a real privilege boundary bypass. On single-site installs, administrators already hold `unfiltered_html`, so the practical risk is low.
- Multisite network operators who can't update immediately should audit `header_image_data` theme mods across sites for non-numeric width/height or suspicious URL values.

**Plugin & theme developers**
- No API change is described. Code that reads `get_custom_header()` should still treat `width`/`height` as untrusted and cast or escape them at output (e.g. `absint()`, `esc_attr()`).
- Themes and plugins that write `header_image_data` directly should sanitize the values on save.

## Technical details

According to the advisory, the fix addresses two points:

- **Input/normalization:** `get_custom_header()` returned the stored `width` and `height` from the `header_image_data` theme mod without integer casting. It also did not sufficiently sanitize the header image URL. Arbitrary strings could therefore flow out of the theme mod.
- **Output:** `Custom_Image_Header::step_1()` (the Appearance → Header admin screen) built a `style` attribute from these values and echoed it unescaped. That is where the stored payload executed.

The patched behavior implied by the advisory is integer-cast dimensions and an escaped `style` attribute. No diff was provided, so exact code changes aren't reproduced here. Exploitation requires the `edit_theme_options` capability.
