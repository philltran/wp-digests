## Summary

The Web to Print Online Designer plugin (listed by Wordfence as "WooCommerce Online Product Designer") through 2.14.0 lacks file type validation on an upload handler reachable without authentication. An unauthenticated attacker can upload arbitrary files to the server, which can lead to remote code execution if a executable file such as PHP lands in a web-accessible location. Version 2.15.0 fixes the issue.

## Impact

**Site owners**
- Any site running Web to Print Online Designer <= 2.14.0 is exposed to unauthenticated exploitation; no account or login is needed.
- Update to 2.15.0 or later as soon as possible.
- If you cannot update immediately, deactivate the plugin until you can.
- Sites that were exposed should be checked for unexpected files (especially `.php` and other executable types) under `wp-content/uploads` and any plugin-specific upload directories, plus signs of webshells or unfamiliar admin users.

**Plugin & theme developers / agencies**
- Audit client sites and any bundled or dependent installs for this plugin, including non-obvious ones such as staging and multisite subsites.
- No API, hook, or code migration is involved; the required action is the plugin update.

**Hosting & platform teams**
- Consider WAF or virtual-patching rules for unauthenticated upload requests to this plugin's endpoints, and blocking PHP execution in upload directories, as defense in depth.

**Headless & REST consumers**
- The advisory does not say which endpoint (AJAX action, REST route, or other) is affected, so no specific route can be named here.

The advisory states the root cause as missing file type validation (CWE-434, Unrestricted Upload of File with Dangerous Type), reachable by unauthenticated users.
