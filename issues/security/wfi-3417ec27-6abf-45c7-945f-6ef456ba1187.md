## Summary

The Request a Quote for WooCommerce plugin (<= 2.9.2) does not validate file extension or MIME type in `afrfq_submit_quote_via_popup()`, the AJAX handler for the multi-page popup quote flow. It passes the attacker-supplied filename straight to `move_uploaded_file()` as the destination. An unauthenticated attacker can therefore drop an executable file such as a `.php` script into a web-accessible temporary RFQ upload directory, which typically leads to remote code execution. No patched version is available.

## Impact

**Site owners**
- Any site running Request a Quote for WooCommerce <= 2.9.2 is exposed if a public quote rule using the multi-page popup flow is enabled.
- No fixed release exists. Wordfence's guidance is to review the details, apply mitigations according to your risk tolerance, and consider uninstalling and replacing the plugin.
- Check the plugin's temporary RFQ upload directory for unexpected files (especially `.php`, `.phtml`, `.phar`) and review access logs for unauthenticated POSTs to `admin-ajax.php` for the popup quote action.

**Plugin & theme developers / agencies**
- Audit client sites for this plugin and its version. Disabling the public popup-flow quote rule may reduce exposure, but the advisory does not confirm this fully closes the hole, so treat deactivation or removal as the safer option.

**Hosting & platform teams**
- A WAF rule or server config that denies PHP execution in the plugin's upload directory (e.g. `wp-content/uploads/` subpaths) is a reasonable stopgap. Note this is a general hardening measure, not something the advisory prescribes.

**Headless & REST consumers**
- The vector is an AJAX handler, not a REST route. No REST-specific action is indicated.

## Technical details

The vulnerable function is `afrfq_submit_quote_via_popup()`, the handler behind the popup quote submission. Per the advisory:

- It performs no file extension check and no MIME type validation on uploaded files.
- It uses the raw client-supplied filename as the destination argument to `move_uploaded_file()`, so both the name and extension are attacker-controlled.
- The destination is a temporary RFQ upload directory that is web-accessible, so an uploaded PHP file can be requested directly and executed.
- Exploitation requires no authentication and depends on a public quote rule with the multi-page popup flow being enabled.

The weakness class is CWE-434 (Unrestricted Upload of File with Dangerous Type). The source record contains no diff or patch, since none exists. The general remediation pattern for this class is to sanitize the name (`sanitize_file_name()`), validate against `wp_check_filetype_and_ext()` with an allowlist, and store via `wp_handle_upload()` or `wp_upload_bits()`. That is a generic fix pattern, not a description of an upstream change.
