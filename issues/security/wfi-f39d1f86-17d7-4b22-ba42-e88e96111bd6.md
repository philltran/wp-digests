# Firebase Authentication < 1.7.1 - Unauthenticated Privilege Escalation via Account Takeover

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-08-20
- **CVE:** [CVE-2026-76793](https://www.cve.org/CVERecord?id=CVE-2026-76793)
- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-288: Authentication Bypass Using an Alternate Path or Channel
- **Affected:** Firebase Authentication (plugin) < 1.7.1
- **Patched in:** 1.7.1
- **Researchers:** Abdullah Kareem
- **Link:** [https://www.wordfence.com/threat-intel/vulnerabilities/id/f39d1f86-17d7-4b22-ba42-e88e96111bd6](https://www.wordfence.com/threat-intel/vulnerabilities/id/f39d1f86-17d7-4b22-ba42-e88e96111bd6)
- **Usefulness:** 5/5

## Summary

The Firebase Authentication plugin for WordPress did not properly verify the email supplied in a session request. An unauthenticated attacker could exploit this to log in as any existing user, including administrators, resulting in full account takeover. Version 1.7.1 fixes the issue.

## Impact

**Site owners**
- Any site running Firebase Authentication < 1.7.1 is exposed to unauthenticated administrator takeover. The CVSS score is 9.8 (Critical).
- Update to 1.7.1 or later immediately.
- If the plugin was active on an unpatched version, review the administrator and other privileged accounts for unexpected creation or modification. Also review recent login activity, and rotate credentials and sessions where compromise is suspected.

**Plugin & theme developers / agencies**
- Audit client and fleet installs for the plugin and its version. Any site using it for social or Firebase-backed login is in scope.
- Custom code that depends on the plugin's session or login endpoint should be retested after upgrading.

**Hosting & platform teams**
- Consider virtual patching or temporarily disabling the plugin on managed fleets that cannot be updated right away.

**Headless & REST consumers**
- The advisory describes the flaw as being in a session request, without naming the endpoint. If your frontend relies on this plugin to establish WordPress sessions, verify the login flow still works after the update.

## Technical details

The advisory is brief. It states only that the plugin "does not properly verify an email in a session request," which allows an unauthenticated attacker to authenticate as another user. The weakness is classed as CWE-288 (Authentication Bypass Using an Alternate Path or Channel).

The record does not name the affected endpoint, function, or file. It also does not describe the exact validation that was added in 1.7.1. Those specifics are not in the source material, so none are stated here.

The general pattern is that the server trusts an email value in the request rather than tying the session to an identity it has independently verified. The advisory does not confirm the precise mechanism.
