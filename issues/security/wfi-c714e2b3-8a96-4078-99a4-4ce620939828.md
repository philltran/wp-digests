# SigmaForms Pro <= 1.4.11 - Unauthenticated Arbitrary File Deletion via Path Traversal in File Upload Field

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-09-01
- **CVE:** [CVE-2026-78657](https://www.cve.org/CVERecord?id=CVE-2026-78657)
- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-22: Improper Limitation of a Pathname to a Restricted Directory ('Path Traversal')
- **Affected:** SigmaForms Pro – AI Generated Forms (plugin) <= 1.4.11
- **Patched in:** 1.4.12
- **Researchers:** Doan Dinh Van, Hieus
- **Link:** [https://www.wordfence.com/threat-intel/vulnerabilities/id/c714e2b3-8a96-4078-99a4-4ce620939828](https://www.wordfence.com/threat-intel/vulnerabilities/id/c714e2b3-8a96-4078-99a4-4ce620939828)
- **Usefulness:** 5/5

## Summary

SigmaForms Pro – AI Generated Forms <= 1.4.11 does not validate file paths in `delete_submission_files`. An unauthenticated attacker can submit a path traversal value through a form's file upload field. The value is stored with the submission, and when an administrator deletes that submission in the admin panel, the plugin deletes the file the path points to. Version 1.4.12 fixes it.

## Impact

**Site owners**
- Update SigmaForms Pro to 1.4.12 or later. The CVSS score is 9.8 (Critical).
- Deleting a critical file such as `wp-config.php` can lead to remote code execution, according to the advisory.
- Deletion only fires when an admin deletes a tainted submission. Until you patch, avoid deleting submissions from the admin panel. Review existing submissions for file-field values containing traversal sequences.

**Plugin & theme developers / agencies**
- Audit any deployments running the plugin and check stored submission data for suspicious upload-field values.
- If you store user-supplied paths or URLs and later act on them with filesystem functions, validate them at use time, not just at input time.

**Hosting & platform teams**
- Consider a virtual patch or WAF rule for requests carrying traversal sequences in form upload fields until sites are updated.

No other configuration or migration steps are described.

## Technical details

The advisory names `delete_submission_files` as the vulnerable function, and the record contains no code or diff. The flow it describes is a stored, deferred attack:

1. An unauthenticated attacker submits a form with a malicious path traversal URL in a file upload field.
2. The plugin stores that value in the database as part of the submission.
3. When an administrator deletes the submission record in the admin panel, `delete_submission_files` uses the stored value to delete files without sufficient path validation, so arbitrary files on the server can be removed.

The weakness is classified as CWE-22. The advisory does not describe the exact fix in 1.4.12. A typical remedy is to resolve the path and confirm it sits inside the uploads directory, but that is an assumption, not something the record states.
