## Summary

The GoDAM plugin (≤1.12.2) contained a critical unauthenticated arbitrary file upload vulnerability. The `save_video_file()` function incorrectly validated uploaded files by trusting the client-supplied `Content-Type` header instead of performing server-side MIME detection, allowing attackers to upload executable scripts directly to a web-accessible directory. Patched in version 2.0.0, this fix closes a direct path to remote code execution on affected sites.

## Impact

- **Site owners & administrators**: Sites running GoDAM ≤1.12.2 are immediately vulnerable to unauthenticated file uploads. Update to ≥2.0.0 to patch.
- **Plugin & theme developers**: No direct API changes, but developers integrating WPForms file uploads should audit custom handlers that bypass `wp_handle_upload()` or rely on client-supplied headers.
- **Hosting & platform teams**: Monitor for suspicious uploads in `wp-content/uploads` and ensure server-level MIME restrictions are enforced as a defense-in-depth measure.
- **Action required**: Upgrade GoDAM to 2.0.0 or later immediately.

## Technical details

The vulnerability resided in the `save_video_file()` callback attached to the `wpforms_process_before_filter` action. Rather than delegating to `wp_handle_upload()`, the function trusted the attacker-supplied multipart `Content-Type` header, preserved the original filename via `wp_unique_filename()`, and moved the raw upload into a web-served directory using `$wp_filesystem->move()`. This bypassed WordPress’s standard MIME and extension allowlists, enabling unauthenticated arbitrary file uploads. The 2.0.0 patch replaces this custom handling with the standard upload pipeline to enforce proper validation before persistence.
