- **Usefulness:** 5/5

## Summary

The Teddy Bear Customize Addon plugin for WordPress, in all versions up to and including 1.0.5, accepts file uploads without validating file type. Unauthenticated attackers can upload arbitrary files to the server, which may lead to remote code execution. No patched version is available.

## Impact

**Site owners**
- Any site running Teddy Bear Customize Addon <= 1.0.5 is exposed to unauthenticated exploitation; the CVSS score is 9.8 (Critical).
- There is no known patch. Wordfence advises reviewing the details and applying mitigations based on your risk tolerance, and notes it may be best to uninstall the plugin and find a replacement.
- Sites that ran the plugin should be checked for unexpected files (especially executable types such as `.php`) in the uploads directory and other writable paths, since the record states RCE may be possible.

**Plugin & theme developers / agencies**
- Audit client sites and composer/plugin inventories for this plugin. If removal is not immediately possible, block access to the plugin's upload-handling endpoint at the WAF or web-server level, or disable script execution in upload directories.

**Hosting & platform teams**
- Consider a fleet-wide scan for the plugin slug and temporary virtual patching or WAF rules until the plugin is removed or fixed upstream.

**Headless & REST consumers**
- The source record does not specify the upload vector (AJAX, REST, or other), so do not assume headless setups are unaffected.

## Technical details

The source record gives only the following: the flaw is classified as CWE-434 (Unrestricted Upload of File with Dangerous Type) and is caused by missing file type validation in the plugin's upload handling. It is reachable without authentication. The record does not name the vulnerable function, file, action, or route, and does not include a proof of concept or code diff, so those details cannot be stated here.
