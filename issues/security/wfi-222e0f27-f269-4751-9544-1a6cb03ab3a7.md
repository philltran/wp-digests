# MemberDash <= 1.8.5 - Unauthenticated Account Takeover via Insecure Direct Object Reference via 'id' Parameter

- **Source:** Wordfence Intelligence
- **Type:** Vulnerability
- **Published:** 2026-09-05
- **CVE:** [CVE-2026-16310](https://www.cve.org/CVERecord?id=CVE-2026-16310)
- **CVSS:** 9.8 (Critical)
- **CWE:** CWE-639: Authorization Bypass Through User-Controlled Key
- **Affected:** MemberDash (plugin) <= 1.8.5
- **Patched in:** 1.8.6
- **Researchers:** Foxyyy
- **Link:** [https://www.wordfence.com/threat-intel/vulnerabilities/id/222e0f27-f269-4751-9544-1a6cb03ab3a7](https://www.wordfence.com/threat-intel/vulnerabilities/id/222e0f27-f269-4751-9544-1a6cb03ab3a7)
- **Usefulness:** 5/5

## Summary

MemberDash versions up to and including 1.8.5 contain an Insecure Direct Object Reference in the registration flow. The plugin trusts a user-supplied `id` parameter without validating it, so an unauthenticated attacker can supply an arbitrary user ID during registration and change that user's password, including an administrator's. The victim receives no notification. The issue is fixed in 1.8.6.

## Impact

**Site owners**
- Any site running MemberDash <= 1.8.5 is exposed to unauthenticated full account takeover, up to administrator level, with no authentication or user interaction required.
- Update to **1.8.6** or later immediately.
- Because no notification is sent to the victim, a compromise may go unnoticed. On sites that ran a vulnerable version, review administrator and other privileged accounts for unexpected password changes or logins, and consider forcing password resets and invalidating sessions. The advisory does not describe indicators of compromise, so this is a precaution rather than a documented detection method.

**Plugin & theme developers / agencies**
- Audit client sites for MemberDash and its installed version across your fleet.
- If you extend MemberDash's registration flow, verify against 1.8.6 after updating. The advisory does not describe API changes.

**Hosting & platform teams**
- This is a critical, unauthenticated, network-exploitable issue (CVSS 9.8). Consider prioritizing a fleet-wide version check and forced update. The advisory does not specify a particular endpoint, so a generic WAF rule may be hard to write.

**Headless & REST consumers**
- The advisory does not say whether the vulnerable path is reachable via REST, AJAX, or a form handler, so do not assume headless setups are unaffected.

## Technical details

The advisory is brief and does not name the vulnerable function, file, or endpoint, and no diff or patch is included in the source material.

What it states:
- **Class:** CWE-639, Authorization Bypass Through User-Controlled Key (IDOR).
- **Vector:** the `id` parameter supplied during registration.
- **Root cause:** missing validation on a user-controlled key. The registration handler accepts a user ID from the request and applies the submitted password to that account without verifying the ID belongs to the registering user or that the caller is authorized.
- **Result:** an unauthenticated request can set the password of any user, including administrators, and no notification is sent to the victim.
- **Fix:** released in 1.8.6. The specific code change is not described in the source.
