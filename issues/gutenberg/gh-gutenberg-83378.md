## Summary

The Comments block now supports button colour styling via the `color.button` block support, allowing the comment form's submit button to be coloured from the block inspector and Global Styles. This closes a gap where link and heading colours were already controllable but the button was not, as part of the broader design-tools consistency effort (related to #43241). The change is a single `block.json` addition plus regenerated docs; no PHP or template changes were required because the submit button already carries the `wp-element-button` class and the block is dynamic.

## Impact

- **Site owners / editors:** The Comments block's submit button can now be styled (text and background colour) from Global Styles → Blocks → Comments and from the block inspector's Styles → Elements panel, including mobile-responsive values. No action required to benefit; the control simply appears where other element colours already did.
- **Theme & block developers:** No code changes needed. The block already uses `get_block_wrapper_attributes()` and the button already has the `wp-element-button` class, so the existing element-colour serialization in `lib/block-supports/elements.php` handles rendering. If you were previously overriding the Comments button colour with custom CSS, you can now use the native control instead.
- **No breaking changes, deprecations, or migration steps.**

## Technical details

The functional change is one line in `packages/block-library/src/comments/block.json`, adding `"button": true` to the existing `color` supports object:

```json
"color": {
  "gradients": true,
  "button": true,
  "heading": true,
  "link": true,
  "__experimentalDefaultControls": { … }
}
```

This mirrors the pattern established for the Columns block (#54104). Because the Comments block is dynamic and renders through `get_block_wrapper_attributes()`, and the submit button in the comment form template already carries the `wp-element-button` class, the element-colour CSS generated by `lib/block-supports/elements.php` applies to it without any PHP-side change. The support flag's role is to expose the button colour controls in the block inspector and Global Styles editor; the front-end rendering path was already in place for any block that does not explicitly opt out of element-colour serialization.

The remaining diff is regenerated documentation: `docs/reference-guides/core-blocks/README.md` and `packages/block-library/src/comments/README.md` both list `button` in the colour supports.
