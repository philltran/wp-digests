## Summary

Block-level preset classes generated by Theme JSON now wrap their block selector in `:where()`, lowering their CSS specificity from `0-1-1` to `0-1-0` to match root-level presets. This resolves a bug where block-level palette rules incorrectly overrode responsive style state styles, both of which use `!important` and previously competed on specificity. The fix applies to both the PHP theme JSON generator and the JS global styles engine, ensuring consistent cascade behavior across the front end and editor.

## Impact

- **Theme & plugin developers:** If you register block-level presets via `theme.json` (`settings.blocks`) or the `wp_theme_json_data_*` filters, the generated CSS selectors now use `:where()`. This lowers specificity, which may change tie-breaks for custom `!important` author CSS targeting the same properties.
- **Site owners using responsive styles:** Responsive color/font presets defined per breakpoint now behave correctly; mobile styles will properly override desktop styles at the intended viewport widths instead of being overridden by block-level desktop presets.
- **No action required** for themes using root-level presets (e.g., Twenty Twenty-Four), as their output remains unchanged.

## Technical details

The diff modifies two generators: `lib/class-wp-theme-json-gutenberg.php` (PHP) and `packages/global-styles-engine/src/core/render.tsx` (JS). Previously, block-level presets appended the block selector directly to the preset class (e.g., `p.has-accent-color` or `.wp-block-group.has-accent-color`). The change wraps the block selector in `:where()` before concatenating the class:

```css
/* Before */
p.has-accent-color { color: var(--wp--preset--color--accent) !important; }
/* After */
:where(p).has-accent-color { color: var(--wp--preset--color--accent) !important; }
```

The JS renderer handles comma-separated selectors (e.g., `h1, h2, h3`) by wrapping the entire list: `:where(h1,h2,h3).has-blue-color`. This ensures both generators emit `0-1-0` specificity, allowing responsive state rules (which also target `0-1-0` with `!important`) to win on source order as intended. Unit tests in `phpunit/class-wp-theme-json-test.php` and `packages/global-styles-engine/src/test/render.test.ts` were updated to assert the new `:where()` output.
