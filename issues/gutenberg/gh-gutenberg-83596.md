## Summary

The Term Count block (`core/term-count`) now supports `dimensions.minWidth` and `dimensions.minHeight` via its `block.json` supports declaration. This is part of the ongoing design-tools consistency effort (related to #43241) to bring the block's available style controls in line with other core blocks. Because the block is server-rendered and its wrapper is produced by `get_block_wrapper_attributes()`, the new support is serialized automatically with no PHP-side change.

## Impact

- **Site owners / theme authors:** Minimum width and height can now be set on the Term Count block via Global Styles (Blocks → Term Count → Dimensions) or the block inspector, including separate mobile values. No code or configuration change is required to use the feature.
- **Plugin & theme developers:** No action required. The support is additive; existing Term Count markup is unchanged when no dimensions are set. If you build custom query-loop templates that embed `core/term-count`, the new controls are simply available in the editor.
- **Headless / REST consumers:** No schema or route changes. The block's serialized attributes are unchanged; dimensions are applied as CSS custom properties on the wrapper element, same as any other block support.

## Technical details

The change is confined to three files:

1. **`packages/block-library/src/term-count/block.json`** — adds the following to the existing `supports` object:

```json
"dimensions": {
    "minHeight": true,
    "minWidth": true
}
```

2. **`packages/block-library/src/term-count/README.md`** — regenerated to list the new `dimensions` support with `minHeight: true` and `minWidth: true`.

3. **`docs/reference-guides/core-blocks/README.md`** — the Term Count entry's supports line now includes `dimensions (minHeight, minWidth)`.

No render-callback, PHP, or JS changes are needed. The block's render function returns early when no term is present and otherwise always outputs a count (minimum `0`), so the wrapper element is never empty and the `min-width`/`min-height` CSS properties always have a box to apply to. The wrapper is generated by `get_block_wrapper_attributes()`, which reads the `supports` declaration and emits the corresponding `--wp--min-width` / `--wp--min-height` custom properties and the matching CSS rules automatically.
