## Summary

The Navigation Overlay Close block now accepts border colour, radius, style, and width through the `__experimentalBorder` supports key in its `block.json`, bringing it in line with other blocks that already expose border controls. A companion CSS fix moves the block's `border: none` reset into a `:where()` selector so it no longer outranks the border styles generated by the block-supports system. No PHP change is required because the block is server-rendered via `get_block_wrapper_attributes()`.

## Impact

- **Theme & block developers:** The Navigation Overlay Close block (used inside the Navigation block's overlay) now exposes border colour, radius, style, and width in both Global Styles and the block inspector. The key is still prefixed `__experimentalBorder`, so it is not yet a stable public API.
- **Site owners / editors:** No action required. Existing close buttons render identically (no border by default). New border controls appear in the editor only when the user navigates to them.
- **No breaking changes, deprecations, or migration steps.**

## Technical details

Two files change:

**`packages/block-library/src/navigation-overlay-close/block.json`** — adds the following to the `supports` object, alongside the existing `shadow`, `spacing`, etc.:

```json
"__experimentalBorder": {
  "color": true,
  "radius": true,
  "style": true,
  "width": true
}
```

Because the block renders server-side through `get_block_wrapper_attributes()`, the serialized border styles land on the `<button>` element automatically; no PHP template change is needed.

**`packages/block-library/src/navigation-overlay-close/style.scss`** — moves `border: none` from the `.wp-block-navigation-overlay-close` rule into the `:where(.wp-block-navigation-overlay-close)` rule that already resets font properties:

```scss
/* before */
:where(.wp-block-navigation-overlay-close) {
  /* font resets … */
}
.wp-block-navigation-overlay-close {
  /* layout … */
  border: none;   /* ← higher specificity than common.scss border rules */
}

/* after */
:where(.wp-block-navigation-overlay-close) {
  /* font resets … */
  border: none;   /* ← zero specificity, so generated border styles win */
}
.wp-block-navigation-overlay-close {
  /* layout … */
}
```

The `:where()` wrapper gives the reset zero specificity, so the border colour/width/style rules emitted by the block-supports system (which target the same class) can override it. Previously, setting a border colour or width without also picking a style produced no visible border because the `border: none` shorthand in the higher-specificity rule won.

Generated documentation is unchanged: the docs generators skip `__experimental`-prefixed keys.
