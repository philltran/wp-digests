## Summary

Fixes a long-standing Global Styles bug where preset references using non-kebab-case slugs (e.g., `n27`) silently failed to apply on the front end. The mismatch occurred because CSS custom property declarations were kebab-cased during generation, but the `var:preset|type|slug` reference conversion performed a verbatim string replacement, causing the browser to look for a non-existent custom property. The fix aligns the reference conversion with the declaration generation, ensuring all preset types resolve correctly regardless of slug casing.

## Impact

- **Theme & plugin developers:** No code changes required. Existing `theme.json` presets with non-kebab-case slugs will now render correctly on the front end without requiring a re-save or schema migration.
- **Site owners:** Previously broken preset references (e.g., fonts, spacing sizes, or duotone filters with slugs like `n27` or `small2`) will now apply as intended. No migration needed.
- **Hosting & platform teams:** No configuration changes. The fix runs at render time in `WP_Theme_JSON_Gutenberg` and does not alter stored user data or REST responses.
- **Breaking changes:** None. The change is strictly additive for previously dead references and provably idempotent for working ones.

## Technical details

The diff modifies `WP_Theme_JSON_Gutenberg::convert_custom_properties()` in `lib/class-wp-theme-json-gutenberg.php`. Previously, the method performed a direct `str_replace( '|', '--', ... )` on `var:preset|type|slug` strings. The updated logic splits the string into parts, checks if it matches a three-segment preset reference, and applies `_wp_to_kebab_case()` to the slug segment before rejoining:

```php
// Before
$unwrapped_name = str_replace( '|', '--', substr( $value, $prefix_len ) );
$value = "var(--wp--$unwrapped_name)";

// After
$parts = explode( '|', substr( $value, $prefix_len ) );
if ( 3 === count( $parts ) && 'preset' === $parts[0] ) {
    $parts[2] = _wp_to_kebab_case( $parts[2] );
}
$value = 'var(--wp--' . implode( '--', $parts ) . ')';
```

This ensures `var:preset|font-family|n27` converts to `var(--wp--preset--font-family--n-27)`, matching the declaration generated by `get_settings_values_by_slug()`. The change is scoped to exact three-segment preset references; all other `var:` syntax remains byte-identical. PHP unit tests in `phpunit/class-wp-theme-json-test.php` verify the kebab-cased output for typography, spacing, and duotone presets.
