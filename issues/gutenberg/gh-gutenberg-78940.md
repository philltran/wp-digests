## Summary

Gutenberg has reverted its upgrade to React 19 due to runtime failures triggered when plugins bundle their own copy of `react/jsx-runtime`. The revert restores the previous React baseline to prevent crashes caused by symbol type mismatches between WordPress core and third-party plugin dependencies.

## Impact

- Plugin & theme developers: No code changes or migration steps are required. After updating packages, the editor will no longer throw errors when encountering legacy elements generated by plugin-bundled React.
- Block editor & platform teams: The JavaScript runtime reverts to the pre-React 19 state. Upcoming adoption of React 19 is deferred until a stable bundling compatibility strategy is established.
- No action required for site owners or headless REST consumers, as this change is confined to the block editor's client-side package ecosystem.

## Technical details

The PR reverts the React 19 upgrade across the Gutenberg monorepo packages (e.g., `@wordpress/element`, `@wordpress/primitives`, `@wordpress/components`). This addresses a breaking behavior in React 19 where encountering an element typed as `Symbol.for('react.element')` against WordPress core's expectations triggers a hard runtime throw. The discussion notes that React 19 originally included a `renameElementSymbol` feature flag to control this behavior, but the merged diff opts for a full dependency revert rather than applying patches or exposing the flag.
