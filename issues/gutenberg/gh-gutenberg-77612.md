## Summary

This pull request automates the generation of per-block API reference documentation directly from `block.json` metadata within the Gutenberg repository. A new generator script produces token-delimited `README.md` files for each core block and category index pages, which are then ingested into the Block Editor Handbook manifest to create a structured 3-level hierarchy (Core Blocks Reference → Category → Block). This replaces the previous flat summary page with detailed, auto-maintained reference docs covering attribute schemas, support flags, context usage, CSS selectors, and markup patterns.

## Impact

- **Block & Plugin Developers:** No code changes or migration required. Core block documentation is now automatically synchronized from `block.json`; existing custom blocks are unaffected unless they opt into the same pattern.
- **Handbook/Documentation Consumers:** The sidebar navigation under `Core Blocks Reference` is restructured. Flat listing is replaced by category index pages and individual block pages with new slugs (`core-block-{name}`), improving API discoverability without breaking handbook routing.
- **Platform & Repository Maintainers:** Commit hooks now enforce documentation regeneration via `lint-staged`. Unstaged generated diffs will fail the commit gate until resolved (e.g., `npm run docs:build` or `--no-verify`). No external configuration changes required.

## Technical details

- Introduces `tools/api-docs/generate-block-docs.mjs`, which scans `packages/block-library/src/*/block.json` and source directories to output 121 block README files in `packages/block-library/src/{block}/README.md` and 8 category pages in `docs/reference-guides/core-blocks/category-{cat}.md`.
- Generated content is wrapped in `<!-- START TOKEN(Autogenerated block API docs) -->` / `<!-- END TOKEN(...) -->` delimiters. This preserves hand-written prose (e.g., `navigation/README.md`) while allowing targeted regeneration of only the token-delimited section on subsequent runs.
- Updates `docs/toc.json`: replaces the flat `core-blocks.md` entry with the `{{blocks}}` token to trigger dynamic manifest population, mirroring the existing `{{components}}` pattern.
- Extends `docs/tool/manifest.js` with `getBlockManifest()`, which reads `block.json` metadata directly and maps each block to its generated README path under a strict 3-level parent hierarchy (`core-blocks` → `core-blocks-{category}` → `core-block-{name}`).
- Integrates into the existing commit pipeline: `docs:blocks-detail` is added to the package source glob in `lint-staged`. The pre-existing sync gate (`docs:check-api-docs-unstaged`) detects drifted token-delimited files and halts commits, ensuring docs stay in sync without auto-committing generated artifacts.
