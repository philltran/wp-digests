## Summary

Gutenberg's repo tooling no longer calls `npx` for binaries that should already be installed. Every such call in CI workflows, the Husky pre-commit hook, release scripts, docs and `create-block` scaffolding now uses `npm exec --no -- <binary>` (or an npm script). With `--no`, npm refuses to download a missing binary instead of installing whatever the public registry serves under that name. This closes a supply-chain gap where a missing local bin, such as a hijackable bin name like `wp-scripts`, could be replaced by an unrelated third-party package.

## Impact

- **Gutenberg contributors:** `.husky/pre-commit` now runs `npm exec --no -- lint-staged`. It fails if `lint-staged` is not installed locally rather than fetching it, so run `npm ci` first. Docs and `AGENTS.md` now say to prefer npm scripts (`npm run format`, `npm run lint:js`, `npm run lint:css`), or `npm exec --no -- <binary>`, adding `--workspace <name>` when another workspace declares the dependency.
- **Release managers:** The manual release steps in `package-release-and-core-updates.md` now use `npm exec --no -- lerna ...`. Some steps gained an explicit `npm ci` before `lerna updated` or `lerna publish`, because the command now fails without a local install.
- **Plugin/theme authors using `@wordpress/scripts`, `@wordpress/create-block`, `@wordpress/env`:** No runtime API change. The scaffolding text generated by `create-block` now tells users to start the local environment through the provided npm script. `npx @wordpress/create-block@latest` examples are deliberately kept, since they name an exact package and hand the reader a tool they have not installed.
- **Forks and downstream CI copying these workflows:** Any job that used `npx <bin>` without a dependency tree needs a `setup-node`/install step first, as `build-plugin-zip.yml` now does.
- **Site owners / hosting / REST consumers:** No action required.

## Technical details

The diff swaps `npx` for `npm exec --no` across these areas:

- **Root-level binaries:** `lerna` (`.github/setup-node/action.yml`, `unit-test.yml`, release commands), `lint-staged` (`.husky/pre-commit`) and `tsc` now run as `npm exec --no -- <bin>`.
- **Workspace-scoped binaries:** where the declaring workspace differs from the root, the call is `npm exec --no --workspace <name> -- <bin>`. `semver` resolves via `@wordpress/release-tools` and `playwright` via `@wordpress/e2e-tests-playwright`.
- **`build-plugin-zip.yml`:** the version-bump job had no dependency tree, so it gains a `./.github/setup-node` step before computing versions.
- **`end2end-test.yml`:** the blob-report merge now runs via the e2e workspace, so its working directory changes. The artifact download path moves from `all-blob-reports` to `test/e2e/all-blob-reports`, and the upload path from `playwright-report` to `test/e2e/playwright-report`.
- **Other touched files (per CodeRabbit's walkthrough; not all visible in the truncated diff):** `packages/scripts/scripts/test-playwright.js` (Playwright browser install now resolves the bundled CLI directly), `packages/env/lib/runtime/playground/index.js`, `tools/release/commands/packages.js` and its test, `tools/release/commands/performance.js`, and `test/e2e/bin/rtc-dev.mjs`.
- **Existing `npm exec` calls guarded:** e.g. `npm exec release-cli -- ...` becomes `npm exec --no release-cli -- ...` in the docs.

```diff
-npx lint-staged
+npm exec --no -- lint-staged
```

A bare `npm exec` behaves like `npx` and downloads missing packages; only `--no` refuses. The PR also notes that `npx` stops resolving hoisted binaries under `install-strategy=linked`.
